# Spec · Thrive 学习模式

版本 0.3 · 适用于 SillyTavern 1.19.0（2026-09-14）

> **本文件只写"读代码看不出来的东西"**：为什么这样做、什么不许做、用户看到什么。
>
> 凡是代码里唯一存在的东西——默认学习块文本、设置项与默认值、工具参数与返回字段、
> 错误码清单、世界书条目模板字段、各类常量上限——一律不在文档里抄第二份。抄了就会漂，
> 上一版的错误码表漏了 7 个、字数说明连续三次对不上，都是这么来的。
>
> 对应位置：`src/prompt.js`（文本与注入）、`src/store.js`（设置与对话状态）、
> `src/tools.js`（工具定义与执行）、`src/targets.js`（读写目标）、
> `src/patch.js`（描述暂存）、`src/diagnostics.js`（错误码目录）。

---

## 1. 范围

**做**：在单人一对一对话中，给模型一组受限工具，让它把对话里值得长期保留的信息写进世界书与角色描述。模式可由用户随时开关，关闭后表现为插件不存在。

**不做**：
- 群聊
- 非线性对话的回滚（消息编辑、删除、回退后不做任何自动修正，交由模型下一轮自行判断）
- 删除世界书条目、停用条目
- 自动创建世界书
- 任何文件系统、网络、设置类操作
- 知识索引、向量检索、摘要压缩等"记忆系统"

---

## 2. 术语

| 词 | 含义 |
|---|---|
| 学习模式 | 一个对话级开关。开启时注入学习块并注册工具 |
| 学习块 | 注入的那段系统提示词，可编辑 |
| 模块 | 两个独立能力：世界书模块、角色描述模块 |
| 可写书 | 用户指定的一本独立世界书，世界书模块唯一的写入目标 |
| patch | 角色描述的"磁盘值 vs 暂存值"的单份差异，等待用户接受或拒绝 |
| 快照 | 直写前的上一版内容，仅供手动恢复 |

---

## 3. 总体结构

```
开关(对话级) ──> 注册工具(shouldRegister) + 注入学习块
                     │
        ┌────────────┴────────────┐
   世界书模块                  角色描述模块
   即时写入                    直写 或 暂存为 patch
        │                          │
   可写书 / 其它已绑定书        character.description
```

关闭时：不注册任何工具、注入置空，请求体与原生一致。

代码分层：业务在 `src/*.js`，界面在 `src/ui/`（一块界面一个文件），`src/ui.js` 只是门面。
界面之间不直接互相调用——谁要在状态变化时刷自己，就把刷新函数登记到 `src/ui/refresh.js` 的
分区表里（见 ADR-030）。

## 4. 状态

两条存储线：跨对话设置走 `extension_settings.thrive`，对话级状态走 `chat_metadata.thrive`。
**键名、类型、默认值、注释只在 `src/store.js` 维护**，本文件不列。

需要代码之外才知道的约定：

- 学习块的三段（`blockCommon` / `blockActive` / `blockPassive`）各自存**空串**表示"这一段用默认文本"，
  不是存一份快照。这样默认文本随版本更新，老用户也能拿到新版；点「恢复默认」就是清回空串。
  三段分开存而不是存一个拼好的整体：拼法会变（见 §6.1），编辑也不该被迫把一个模式的话写进另一个。
  老版本只有一个 `blockText`，`ensureSettings` 在第一次读到它时搬进 `blockCommon` 并删掉旧键——只搬一次，
  否则用户清空通用段之后会被旧值复活。
- `compactPrompt`（超限时的压缩指令）同一套约定：空串 = 用默认文本。它与学习块的分工是
  **事实归代码、态度归用户**——"多少字、超了哪个阈值、append 还能不能写"永远由调用点拼，
  可配的只有"为什么压、压完留下什么态度"那段。所以同一条设置能同时用在描述和世界书上，不会说错话。
- `reads` 在用户每发一条消息时清空（一轮 = 一条用户消息 + 其后的全部工具调用与递归续写）；
  `patch` 与 `backups` 不清。
- `backups.lore` 每条既是恢复用的快照，又是面板「已写入」列表的一行（ADR-022），两者不各存一份。
  `action` 决定恢复动作：`created` 恢复 = 从书里删掉这条，`rewritten` 恢复 = 写回正文与关键词。
  `restoredAt` 非空即已恢复过，面板不再给按钮。
- 老聊天里缺 `id` / `action` 的记录必须还能读：`action` 按 `before` 是否为空推断，`id` 用 `at + 下标` 补齐。
  不做迁移脚本，读时兼容即可。

## 5. 开关与模块

- 学习模式是**对话级**开关；新对话取 `enabledByDefault`。
- 入口：输入框左侧徽章（开 / 关浮动面板）、浮动面板里的两个开关、扩展设置面板、
  `/thrive` 斜杠命令（`on` / `off` / `status` / `panel`）。
  工具不可用（`isToolCallingSupported()` 为 false）时徽章置灰、面板里只报第一条原因，开关不切换状态。
- 关闭时不向聊天流插入任何消息。
- 切换开关不重载页面，不改变工具注册表，只改变 `shouldRegister` 的返回值。
- **两个模块都为 false 时禁止启用**：开关置灰，提示"请先开启至少一个模块"。
- 世界书模块开启但 `writableBook` 为空时视为未就绪：世界书工具不注册，设置页提示"请先选择可写世界书"。
- 关闭描述模块时，已存在的 patch 仍可接受或拒绝，只是不再产生新改动。

### 5.1 被动学习

与主动开关并列的第二条打开方式：**不常开**，但按判据自动"借"一轮。

| 项 | 规定 |
|---|---|
| 判据 | ① 条数：距上次学习累计 N 条可见消息；② 关键词：最近一轮 User / Assistant 消息命中。两者是 **or** |
| 计数口径 | 只数 `chat` 里非 `is_system` 的消息（工具日志不算）；一问一答算 2 条 |
| 关键词口径 | 只扫最近一条 User 与最近一条 Assistant 的 `mes`；大小写不敏感、子串匹配；世界书 / 作者注释 / 预设不参与 |
| 触发 | 只挂一次记号（`pending`），不立刻改开关。下一次生成时把它当作"已开启"：注入学习块 + 注册工具 |
| 结束 | 角色消息落盘（`MESSAGE_RECEIVED`）即结算：清掉记号、把进度基线推到当前条数。生成被中途停止**不算**结算 |
| 与主动的关系 | 主动开着时被动不触发，并把进度归零；打开主动会丢掉已挂的记号 |
| 同一轮 | 结算时记下这一轮用户消息的哈希，同一轮的第二次评估直接跳过——避免角色复述关键词导致连开两轮 |
| 落点 | 开关与判据是**全局**设置；记号与进度是**对话级**状态 |

- 提示：触发时 toast 说清原因，徽章被动段变成「待学」并呼吸闪烁；注入的学习块末尾追加一段
  "本轮为自动触发、只在这一轮有效"的说明（`getOnceNotice()`），否则模型会以为学习模式一直开着。
- 手动入口：设置页「现在触发一次」与 `/thrive once`，不受被动总开关限制——用户明确要求就给他一轮。
- 静默生成（`dryRun`）不标记、不结算：摘要与翻译不该把用户等的那一轮学习吃掉。

## 6. 学习块

### 6.1 三段结构

学习块不是一段文本，而是**三段拼出来的**：

| 段 | 设置键 | 什么时候带 | 默认倾向 |
|---|---|---|---|
| 通用 | `blockCommon` | 两种模式都带 | 工具层 / 正文层分工、写到哪里、怎么写、规则 |
| 主动 | `blockActive` | 主动模式那一轮 | 积极提问、逢话必记，宁可记小不要漏 |
| 被动 | `blockPassive` | 被动学习借来的那一轮 | 只记关键信息、减少工具调用 |

注入时按「通用 + 当前模式段」的顺序拼，中间空一行（`composeBlockText()`）。
两段说的话**重合时以模式段为准**——它排在后面，模型读到的最后一句是它；
文本层面不做去重，那既猜不出"哪句算重合"，也会把用户的话悄悄改掉。

当前跑哪套模式由 `store.getLearningMode()` 决定：主动开关开着就是主动，否则有待学记号就是被动，
都没有则不注入。**两条路径重合时主动优先**，与"主动开着时被动不触发"是同一条规则。

### 6.2 默认文本

在 `src/prompt.js` 的 `DEFAULT_BLOCK_COMMON` / `DEFAULT_BLOCK_ACTIVE` / `DEFAULT_BLOCK_PASSIVE`，
**本文件不再存副本**。三段的元信息（设置键、默认值、界面标签）集中在 `BLOCK_TEXT_PARTS`，
界面按它渲染，加一段只改这一张表。改默认文本时守这几条：

- **静态**：不含条数、模块名、待办数、时间等任何动态内容。这段文本每轮都进请求，动态内容既
  让前缀缓存失效，也会让模型的判断标准随状态漂移。
- **拼完不超过 1K 字**（`countChars` 口径：不计空白），当前主动约 520、被动约 530，留有余量。
- **点到为止**：只给判断标准（什么值得记、写到哪里、什么时候该问），不写"具体该怎么写"的长例子与
  示范句式。规则写得越细，模型越照着套模板、越不肯自己判断——文本也会迅速膨胀到上限。
- **通用段不表态"记多少"**：积极还是克制属于模式差异，一律写到模式段里，
  否则改一种模式的语气会连带影响另一种。
- 只用 `{{char}}` / `{{user}}` 两个宏，其余花括号内容一律会被当宏处理。模式段可以只用其中一个。

### 6.3 注入规则

| `blockPosition` | 行为 |
|---|---|
| `tail` | 落在消息数组末位；每轮重新计费，但不打断前缀缓存 |
| `head` | 进 system 区；每次开关都会让整段 system 前缀重新 prefill |
| `none` | 插件不注入，用户自行放进预设 |

- 注入前插件自己 `substituteParams(text)`。原因：ST 对两种位置的宏处理路径不一致，只有自己替换才能保证
  两种位置表现相同；尾部注入确定不替换。
- 关闭时不是"不设置"，而是显式写空串——`getExtensionPrompt` 会过滤空 value，条目才彻底从请求里消失。
- `head` / `none` 两个选项在设置页各带一条警告（见 `getPositionHint()`），因为代价与后果都由用户承担。

## 7. 工具契约

四个工具，名字固定，`stealth: false`。参数 schema、描述文案、返回字段以 `src/tools.js` 为准。

| 工具 | 作用 | 注册条件 |
|---|---|---|
| `lore_read` | 检索条目 / 取标题总览 | 对话开启 && 世界书模块 && 可写书非空 |
| `lore_write` | 按标题 upsert 条目 | 同上 |
| `desc_read` | 读角色描述全文 | 对话开启 && 描述模块 |
| `desc_write` | 追加或整段改写角色描述 | 同上 |

模型依赖、但代码里不显眼的三条：

- **错误返回统一形状** `{ ok: false, error, hint }`。`hint` 只说事实与下一步动作（见 §11.5）。
- **错误码清单以 `src/diagnostics.js` 的 `ERROR_HINTS` 为唯一来源**，文档不再列。
  调用点的文案更具体时优先用调用点的。
- `lore_write` 的 `keys` 只在新建时必填；改写时省略表示沿用原关键词，给了就整体替换。
  `constant` 新建固定 false，改写保留原值——不替用户改触发方式。

## 8. 读写一致性

- **轮次**：用户每发一条消息清空 `reads`；之后的所有工具调用（含 ST 的递归续写）算同一轮。
- **写入前置检查顺序不可调**：模块是否开启 → 本轮有没有读过该目标 → 读到的哈希是否仍一致 → 其余校验
  （关键词、长度、空值）。顺序本身就是给模型的反馈：先说"这个模块关了"比说"你没读过"有用。
- **自写登记**：写入成功后立刻把新内容哈希写回 `reads`，否则同一轮里第二次写会被自己挡住。
- 哈希只用于判断"内容是否变过"（FNV-1a，UTF-16 码元），不做任何安全用途。
- `lore_read` 只在**返回过正文**时登记读取，只给标题的总览不算读过；否则"读完发现书里没有 → 新建"
  这条路径会被自己的规则卡死。

## 9. 权限矩阵

| 模块 | 工具 | 可读 | 可写 |
|---|---|---|---|
| 世界书 | `lore_read` `lore_write` | 可写书；`readScope=bound` 时含当前角色绑定的其他书 | 仅可写书 |
| 角色描述 | `desc_read` `desc_write` | `description` | `description` |

**禁止**：`personality`、`scenario`、`first_mes`、`mes_example`、角色名、头像、预设、正则、任何设置、任何文件。

目标类型与模块不符时直接拒绝，不降级。

- **关闭 = 工具从请求里消失**，而不是"注册了再拒绝"。模型看不见不该用的工具，才不会反复试。
- **两个都关**：徽章置灰、点击只给原因不切换；当前对话若已开启则自动关闭并提示一次。
  兜底放在 `refreshUI()` 而不是 change handler——手改 `settings.json` 也要能被纠正。
- 关闭模块**不清理**任何已写入的内容；只在面板里提示"学习块里对应段落建议一并删掉"，不自动改用户文本。

## 10. patch（角色描述暂存）

结构在 `src/patch.js`，这里只写行为要求：

- 同一时刻最多一份 patch，状态只有 `pending` / `conflict` / `applied`。
- **合并基准是 `after`**：暂存期间再来一笔写入，以 `after` 为基准算新的 `after`，`before` 不动。
  同时 `desc_read` 在暂存期间返回 `after`——所以版本校验与 `append` 的基准都必须是 `after`，
  用磁盘值会让第二笔永远 `STALE_READ`。
- **冲突期间禁止写入**（`PATCH_CONFLICT`）：冲突是"用户还没做完的决定"，这时再合进一笔，
  等于把"用户手改版"和"模型新版"混成一份，谁覆盖谁没有答案。等用户点完再说。
- 应用前校验磁盘哈希：不符则转 `conflict`，不写入；用户只能「强制覆盖」或「拒绝」。
- **拒绝不动 `reads`**：模型可能刚读到暂存文本，把磁盘哈希写进去等于假装它读过磁盘，下次会覆盖没见过的内容。
  应用成功则必须更新 `reads`。
- 用户只能接受或拒绝整份 patch，不能编辑 `after`。
- 关闭 patch 功能时若存在 pending，必须先应用或先拒绝，不允许静默丢弃。

## 11. 世界书写入

### 11.1 目标

只写 `writableBook`，书必须已存在。选择器数据源用 `ctx.getWorldInfoNames()`
（1.19 新增，返回 `world_names` 的副本），不要直接读内部变量。列表里对两类加提示：

- 当前角色的绑定书（`character.data.extensions.world`）：提示「这是角色自带的世界书，改动会随角色卡一起分发」。
- 疑似卡内嵌书（与某张卡的 `character_book.name` 同名）：提示「卡内嵌副本与独立文件不会自动同步」。

卡内嵌 `character_book` 本身不作为写入目标——写入只会落到 `worlds/` 下的文件，两边会分叉。

字段映射与新建条目的固定值都在 `src/targets.js`，本文件不列。只有一条代码里看不出来的：

> 新建条目必须**显式**写 `triggers: []`。它表示"所有生成类型都参与"，缺这个字段的条目在部分生成
> 类型下会静默不生效——不是报错，是根本不进上下文，排查时极难发现。

### 11.2 落盘

`loadWorldInfo` → 修改 → `saveWorldInfo(name, data, true)`，第三个参数必须显式给 `true`：
默认走防抖保存，切对话或关页面的几百毫秒窗口足够丢一次写入。

`saveWorldInfo` 会把对象**按引用**塞进缓存，别在保存后复用同一对象做第二次修改——每次写前重新 load。

### 11.3 换书

切换时弹确认："新书里没有旧书的内容，角色不会记得它们。" 切换后 `lastBook` 置空，
下次 `lore_read` 触发 `switched` 提醒。新对话第一次读取也会带一次提醒，这是同一个机制，不用特判。

### 11.4 激活状态

写进文件 ≠ 会生效。ST 只扫描**在扫描范围内**的书，三条路：角色自带（`character.data.extensions.world`）、
聊天级绑定（`chat_metadata.world_info`）、世界书面板里手动勾选。前两条之外的书写进去，条目只是躺在文件里。

`selected_world_info` 没有公开 API（只在 `#world_info` 的 change 事件里重建），判定只能读 DOM：
`#world_info` 的 `selectedOptions` → `option.value`（是 `world_names` 的下标）→ 书名。
判定结果三态：`true` 会被扫描 / `false` 不会 / `null` 判断不了（面板没渲染，按"已激活"处理，宁可漏报不误报）。

**不自动把书加进激活列表**（ADR-021），只把状态说清楚：

| 位置 | 未激活时 |
|---|---|
| `lore_read` 总览 | `note` 前面加一句「这本书当前没有激活。」 |
| `lore_write` | 照常写入，`note` 换成「已写入「X」，但这本书当前没有激活。」 |
| 设置面板 | 转警告样式，写明没激活 + 去哪勾 |

已激活 / 判断不了时保持原文案，不能对模型说假话。

### 11.5 工具返回只说事实

不解释原因、不替模型组织台词——「为什么不行」「你该怎么对用户说」是模型自己对用户讲的话，
工具返回值替它决定就变成了台词注入。

分界看**动作归谁**：模型自己该对数据做的动作（"考虑合并重复条目""先调 `lore_read`"）可以写；
要用户去做的事（"请提醒用户勾选""请用户清理"）以及"为什么这样"的解释，都不写。
所以上表里工具侧只有一句"没有激活"，完整解释留在面板（给用户）和模型自己（给对话）。

## 12. 角色描述写入

- 只写 `description`；写入后同步更新本地 `characters[chid].description`，若角色编辑面板开着且输入框
  未聚焦，同步其 textarea——不刷新会让用户以为没写进去。
- `append` 语义：`当前文本 + 空行 + text`，当前为空则不补空行。格式细节只在此处规定一次，
  因为它是用户可见的排版结果。
- 长度校验按**写入后的总长度**判断，不看本次增量。超软阈值只提醒，超硬上限才拒绝。
- 超阈值的 hint 一律 = 调用点的事实句 + `compactPrompt`（见 `src/compact.js`）。
  默认文本只交代目的与"压完要承认记忆有损"，不规定怎么压：规则越细，模型越会照着砍成一份模板摘要。
- 直写前把当前值存入快照（只留 1 版）。

## 13. 可观测性

| 层 | 内容 |
|---|---|
| 徽章 | 输入框左侧的固定尺寸图标，只开关面板；图标颜色表示模式状态（待学时呼吸），有未处理的改动时右上角带计数，不可用时置灰 |
| 聊天流 | 当轮只是一行纯文本日志，不留大块 HTML |
| 面板 | 三个分区：模式（主动 / 被动开关）、待确认（patch）、已写入（世界书写入记录，只读，带恢复按钮）；由徽章开关，收起时整块隐藏 |
| 设置页诊断 | 先问 `ctx.isToolCallingSupported()`，为 false 时才细分原因并各给一句"去哪改" |

- patch 的 diff 默认折叠未改动行，只展开差异段。**中文描述常常整段一行**，不按句读切开就是
  "改一个字 = 整段删 + 整段增"，折叠也会失去意义。
- 「已写入」每条只读，唯一动作是恢复（`created` 的按钮文案为「撤销新建」）；恢复前弹确认，
  恢复后作废该条目的读取登记。
- 面板收起后只留一行摘要，有新 patch 时自动展开。

### 13.1 工具日志

两个时机，两步处理：

1. **当轮压缩**：工具调用完成时把该条消息改写成一行纯文本（`[thrive] lore_write → {"ok":true,...}`，
   总长截断 200 字）。结果里的长字符串只留长度、数组只留条数。`extra.tool_invocations` 不动——
   第 2 步要靠它识别。
2. **下一轮清理**：用户下一条消息发出时，删掉更早消息的 `extra.tool_invocations`。消息与其 `mes` 保留、
   继续显示；ST 的 `coreChat` 过滤条件会因此把它们排除出上下文。

两步都只处理**全部由 Thrive 工具构成**的消息，混合了其他扩展调用的消息原样留给 ST（ADR-023）。
`dropTraces = false` 时跳过第 2 步。

## 14. 失败模式

| 现象 | 处理 |
|---|---|
| 后端不支持 tools / 函数调用未开 | 徽章置灰；设置页指出具体要改哪一项 |
| 后处理模式为 `merge` / `semi` / `strict` | 这些模式会移除工具消息；指向 `merge_tools` 等带后缀的版本 |
| 可写书未激活 | 照常读写；`lore_*` 的 `note` 只说"当前没有激活"，完整解释留给面板（§11.4） |
| 模型不调工具 | 只在工具描述里给判断标准，不主动催促 |
| 模型写错目标 | `MODULE_DISABLED` + 明确提示，不代它改道 |
| 递归 5 轮耗尽 | ST 自行停止；插件不额外处理 |
| 世界书被用户手改 | 下次写入 `STALE_READ` |
| 消息被删/编辑 | 不回滚任何写入 |

## 15. 已知限制

1. 多标签页同时打开同一聊天时，`chat_metadata` 后写覆盖先写，patch 可能丢失。
2. 关闭 patch 后，描述改写不可撤销（仅有一版快照）。
3. 世界书没有 patch，误写只能靠快照或手动编辑。
4. 关闭插件后，已写入的世界书与角色描述继续生效。
5. `head` 注入位置在频繁开关时会显著增加费用。
6. 每次工具日志清理会在历史中间段产生一次缓存断点。

## 16. 依赖的 ST 行为（按 1.19.0 复核）

不记行号——源码可搜。这些是会影响设计的**行为**，不是接口清单：

| 行为 | 影响 |
|---|---|
| 注册的工具表为空时，请求体里连 `tools` 键都没有 | 关闭/门控关闭时才能做到"与原生一致" |
| 工具调用后自动续生成，递归上限 5 | 一轮内可能有多笔写入；`reads` 的自写登记必须扛得住 |
| `stealth` 调用会吞掉正文 | 我们用 `stealth: false`，工具结果要能被用户看见 |
| 尾部注入不经过 `substituteParams`，头部经过 | 只能由插件自己替换宏 |
| 后处理白名单只认带 `_tools` 后缀的模式 | 诊断文案的依据 |
| `coreChat` 按 `extra.tool_invocations` 过滤 | 清理日志靠删这个字段实现 |
| 条目模板含 `ignoreBudget` / `outletName` / `triggers` | 新建条目必须显式写 `triggers`（§11.1） |
| `getWorldInfoNames()` 返回列表副本 | 选择器数据源；下标会随书单变化，不要缓存 |
