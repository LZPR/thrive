# Spec · Thrive 学习模式

适用于 SillyTavern 1.19.0（2026-09-14）

> **本文件只写"读代码看不出来的东西"**：为什么这样做、什么不许做、用户看到什么。
> 默认提示词、设置项与默认值、工具参数与返回字段、错误码清单、条目模板字段、各类常量上限——
> 一律只在源码里存在一份，这里不抄第二份。抄了就会漂。

---

## 1. 范围

**做**：在单人一对一对话中，给模型一组受限工具，让它把对话里值得长期保留的信息写进世界书与角色描述。模式可随时开关，关闭后表现为插件不存在（工具常驻是唯一例外，用一段提示词代替「工具消失」）。

**不做**：群聊；非线性对话的回滚（消息编辑、删除、回退后不做任何自动修正）；删除或停用世界书条目；自动创建世界书；任何文件系统、网络、设置类操作；知识索引、向量检索、摘要压缩这类"记忆系统"。

---

## 2. 术语

| 词 | 含义 |
|---|---|
| 学习模式 | 一个对话级开关。开启时注入学习块并注册工具 |
| 学习块 | 注入的那段系统提示词，可编辑 |
| 可写书 | 世界书工具唯一的读写目标，按对话选。统一描述模式下固定为角色同名书 |
| patch | 角色描述的"磁盘值 vs 暂存值"的单份差异，等待用户接受或拒绝（`card` 模式恒有，ADR-046） |
| 快照 | 直写前的上一版内容，仅供手动恢复 |

---

## 3. 结构与界面分工

```
开关(对话级) ──> 注册工具 + 注入学习块
                     │
        ┌────────────┴────────────┐
   世界书工具（那本书）        角色描述工具（卡 / 条目）
   即时写入                    暂存为 patch / 直接写条目
```

关闭时：不注册任何工具、注入置空，请求体与原生一致。

界面按**作用域**分两处，不按功能模块分（ADR-043）。规则只有一句：**换一场对话，它该不该变？**

- **浮动面板**：这一场的全部东西——两个开关、描述存哪儿、可写书、「现在触发一次」、待确认改动、写入记录。
- **扩展设置页**：跨对话一致的设置——新对话默认、被动判据、数值上限、提示词、面板外观。这一页不随对话变化（ADR-045）。

两处界面都不直接互相调用：谁要在状态变化时刷自己，把刷新函数登记到 `ui/refresh.js` 的分区表里（ADR-030）。

## 4. 状态

两条存储线：跨对话设置走 `extension_settings.thrive`，对话级状态走 `chat_metadata.thrive`。键名、类型、默认值只在 `src/store.js` 维护。需要代码之外才知道的约定：

- 学习块三段与压缩指令都用**空串表示"用默认文本"**，不是存快照。这样默认文本随版本更新、老用户也能拿到新版；「恢复默认」就是清回空串。
- 压缩指令的分工是**事实归代码、态度归用户**：「多少字、超了哪个阈值、还剩多少余量」永远由调用点拼，可配的只有"为什么压、压完留什么态度"那段。所以同一条设置能同时用在描述和世界书上，不会说错话。
- 编辑器里改了立刻生效、落盘防抖。
- 快照记录**一条数据两用**：既是恢复用的快照，又是面板「已写入」的一行（ADR-016）。老聊天里缺字段的记录读时兼容，不做迁移脚本。

## 5. 开关与模块

- 学习模式是**对话级**开关；新对话取 `enabledByDefault`。
- 入口：输入框左侧徽章（开关面板）、面板里的两个开关、`/thrive` 斜杠命令。
- 关闭时不向聊天流插入任何消息；切换不重载页面，只改变 `shouldRegister` 的返回值。
- **没有模块开关**（ADR-046）：世界书工具常在；角色描述工具两种存储模式都有，只是落点不同。
- 没选可写书时视为未就绪：世界书工具不注册，面板与工具清单都写明"没选可写书"。描述工具不受影响。
- 读范围只有一本：能读到的条目就是能改的那一条。

### 5.1 被动学习

与主动开关并列的第二条打开方式：**不常开**，按判据自动"借"一轮。

| 项 | 规定 |
|---|---|
| 判据 | ① 距上次学习累计 N 条可见消息；② 最近一轮 User / Assistant 消息命中关键词。两者是 **or** |
| 计数口径 | 只数非 `is_system` 的消息（工具日志不算），一问一答算 2 条 |
| 关键词口径 | 只扫最近一条 User 与最近一条 Assistant 的正文；大小写不敏感、子串匹配；世界书 / 作者注释 / 预设不参与 |
| 触发 | 只挂一次记号，不立刻改开关。下一次生成时当作"已开启"：注入学习块 + 注册工具 |
| 结束 | 角色消息落盘即结算；生成被中途停止**不算**结算 |
| 与主动的关系 | 主动开着时被动不触发，并把进度归零 |
| 落点 | 判据是**全局**设置（设置页）；开关、记号与进度是**对话级**（面板，ADR-044 / ADR-045） |

- 触发时 toast 说清原因，徽章被动段变成「待学」并呼吸闪烁；注入的学习块末尾追加一句"本轮为自动触发、只在这一轮有效"，否则模型会以为学习模式一直开着。
- 手动入口「现在触发一次」不受被动开关限制——用户明确要求就给他一轮。
- 判据两项都空着时组内出小字"被动学习开着也不会触发"。这是空转，不是错误，所以不用警告色。
- 判据与开关分居两处是有意的：**判据是"我隔多久想被提醒一次"（对所有对话一致），开关是"这一场要不要"**。面板只**读**判据来算"还差几条"，一条都没配时指路到设置页。
- 静默生成（摘要、翻译）不标记、不结算：不该把用户等的那一轮学习吃掉。

### 5.2 工具常驻

`toolsResident`（默认关，ADR-037）：

| 关 | 开 |
|---|---|
| 关闭学习模式 → 工具从请求里消失，前缀缓存从最前面失效 | 工具定义一直留着，可用性改由「工具指令」那段文字表达 |
| — | 仍可能被调用：`guardAction` 在学习模式没开 / 模块关闭 / 没选书时返回 `TOOL_UNAVAILABLE` |

工具定义是请求里最大的一块，常驻会一直占着这部分 token，换来开关模式时缓存不断。频繁开关（被动学习、临时借一轮）时打开；整场只开一次时关着更省。常驻只影响"定义在不在请求里"，可用性判定只有 `src/tool-state.js` 一份。

### 5.3 角色描述的存储模式

`descStorage`（对话级，ADR-042）：`card`（默认，老机制）/ `worldbook`（统一使用世界书）。两套机制并存，切回即恢复，不做一次性迁移。

| 项 | `card` | `worldbook` |
|---|---|---|
| 正文在哪 | 角色卡 `description` | 与角色同名那本世界书的 `【角色描述】` 条目 |
| 怎么进上下文 | ST 原生角色卡注入 | 世界书常驻条目 |
| 暂存 / diff | 有 | 无 |
| 撤销 | 描述快照单槽 | 世界书快照（面板「已写入 → 恢复写入前」） |

- **切换不做内容迁移**：条目从空白开始，角色卡上原有的文字既不搬走也不清空。卡上残留的描述仍由 ST 注入，但面板**不为此出警告**（ADR-046）：用户改的不是这一处、也不知道该怎么处理，说一句"卡上还留着 N 字"只会让人一头雾水。插件自己不去改用户的卡。
- `worldbook` 模式下**可写书固定为角色同名书**：描述就在那本书里，允许另选一本会让"描述写哪儿"出现两个答案。面板把下拉置灰并显示出真正的目标书。
- 例外：角色改过名、描述此前已落在绑定书里时，仍认那本旧书（否则改名等于再建一本空书）。此时"可写书"按现名给，两条提示各自写出书名——不静默分叉，也不自动搬家。
- `desc_*` 四个工具的名字与参数不变，只换落点；`lore_*` 六个工具**看不到也改不了**这条条目（`RESERVED_ENTRY`）。
- 条目必须常驻且启用：每次写入都校正常驻与停用标志。这两个字段是"描述"这个语义的基础，被用户或别的插件改掉之后必须掰回来。
- 切回 `card` 时把条目停用（内容保留），否则两处内容会同时进上下文。
- 书怎么选，顺序固定：绑定书里已有该条目 → 与角色同名的书 → 首次写入时新建同名书。
- **不自动**改动世界书的激活列表，书没被扫描到时面板转警告并指出去哪勾（见 §11）。
- 切换时有未决 patch → **拒绝切换**，先让用户在面板里写入或丢弃。

## 6. 提示词

### 6.1 卡片与分界线

设置页「提示词」是一列卡片，顺序存在 `promptOrder`。卡片不是"一个功能一个框"，而是**注入顺序的具象**：工具指令、学习块三段、压缩指令各一张，外加一张**不注入的分界线卡**（「其它提示词」）。

- 分界线前的卡进系统提示词区，排在它后面的进对话尾部。拖动分界线等于整体换边。
- 同一组按顺序用空行拼成**一段**再注入，空段丢掉。
- 顺序不再有"模式段必须在后"的约定：拖到哪就是哪，两段话重合时以谁为准由用户的顺序决定。
- 默认文本的约束：静态、拼完不超过 1K 字、点到为止、通用段不表态"记多少"；只在 `src/prompt.js` 存一份。
- `promptInject` 关掉后插件完全不碰提示词：用户在预设里自己放。压缩指令本来就不注入，不受影响。

### 6.2 工具指令与宏

工具常驻之后，可用性不能再靠"注册 / 不注册"表达，只能靠这段文字：`{{tool}}` 在工具可用时展开成工具名、不可用时展开成空，`{{!tool}}` 反之。

- 认不出的花括号原样保留（`{{char}}` / `{{user}}` 还要交给 ST）。
- **模板里有工具宏、但全部展开为空时整段不注入**——默认文本写的是"下面这些工具不可使用"，全都可用时它只剩一句没头没尾的引导语。
- 清单只收「看得见、但不能用」的工具。模块关掉 / 没选可写书时工具根本没注册，写进清单只会让模型去找一个不存在的名字。
- 按这套判定，这段实际只在**学习模式关闭**时出现——它要说的就是"工具还在，但这轮别用"。
- 默认放在分界线下方：它每开关一次模式就变一段，放头部会让 system 前缀跟着失效。
- 设置页另有一块折叠的**工具清单**（只读）：直接读 ST 的注册表，界面上写的描述就是请求里发的那份（ADR-038）。

## 7. 工具契约

十个工具，名字固定，`stealth: false`。参数 schema、描述文案、返回字段以 `src/tools.js` 为准。

命名是 `<目标>_<动词>`，动词只有 read / list / add / append / replace / rewrite。读一律叫 `read`——同一个动作两种叫法，模型要多花一步去分辨它们是不是一回事（ADR-032）。

| 工具 | 作用 | 写入前置 |
|---|---|---|
| `lore_list` | 目录：已启用条目的标题 | — |
| `lore_read` | 单条正文 / 正则片段 | — |
| `lore_add` | 新建条目 | 目录读过 |
| `lore_append` | 追加正文、追加关键词 | 见过这条标题 |
| `lore_replace` | 正则替换正文片段 | 同一 pattern 预读命中 |
| `lore_rewrite` | 整段替换正文 | 该条全文已读 |
| `desc_read` | 描述全文 / 正则片段 | — |
| `desc_append` | 末尾追加一段 | 读过描述 |
| `desc_replace` | 正则替换片段 | 同一 pattern 预读命中 |
| `desc_rewrite` | 整段重写 | 全文已读 |

模型依赖、但代码里不显眼的三条：

- **错误返回统一形状** `{ ok: false, error, hint }`。`hint` 只说事实与下一步动作。
- **错误码清单以 `src/diagnostics.js` 为唯一来源**，文档不列。
- **两个 `rewrite` 都只改正文**：标题是定位键、关键词是触发方式，压缩正文时一律保留原值。要加关键词走 `append`，要改标题只能由用户在世界书编辑器里改。

## 8. 读写一致性

**写入前置分四级**，读得越少，能写的越少（ADR-007）：目录 → `add`；见过标题 → `append`；同 pattern 预读命中 → `replace`；读过全文 → `rewrite`。

- 分级的理由：只看过标题就允许整段覆盖，"先读后写"就只是口号；反过来，追加与替换由插件在盘上的完整正文上做增量，模型手里那半截文本冲不掉后半段，所以不需要全文。
- **检查顺序不可调**：学习模式是否开着 → 目标是否可用 → 前置级别够不够 → 其余校验。顺序本身就是给模型的反馈：先说"现在不能写"比说"你没读过"有用。
- **局部编辑不做 `STALE_READ` 阻断**；只有整段重写要求读取时的哈希与当前一致。
- **自写登记**：写入成功后把新内容哈希写回，并作废该目标上所有 pattern 预读——正文变了，之前看清的命中位置就不再成立。不登记的话，同一次回复里的第二笔写入会被自己挡住。
- 全文读取被截断时**不登记全文**：拿半截文本去重写会冲掉后半段。

## 9. 权限

| 目标 | 可读 | 可写 |
|---|---|---|
| 世界书 | 可写书（`lore_list` / `lore_read` 都只这一本） | 仅可写书 |
| 角色描述 | 当前落点的那份（角色卡或保留条目） | 同左 |

读范围收成一本是有意的（ADR-046）：读到一条改不了的内容，模型无法判断它算"已经记在别处"还是"还不存在"，两个答案都会让它做错事。

`【角色描述】` 不属于世界书条目的权限范围：目录不列它，`lore_*` 按标题一律拒绝；反过来 `desc_*` 也不会碰任何普通条目。

**禁止**：`personality`、`scenario`、`first_mes`、`mes_example`、角色名、头像、预设、正则、任何设置、任何文件。目标类型与模块不符时直接拒绝，不降级。

**关闭 = 工具从请求里消失**，而不是"注册了再拒绝"。模型看不见不该用的工具，才不会反复试。

## 10. patch（仅 `card` 模式）

统一使用世界书的模式没有 patch：描述直接写成一条条目，面板不提供 diff。

- 同一时刻最多一份 patch，状态只有 `pending` / `conflict` / `applied`。
- **合并基准是暂存值**：暂存期间再来一笔写入，以它为新基准继续合，磁盘那份不动。读取在暂存期间也返回暂存值——否则第二笔必然 `STALE_READ`。
- **冲突期间禁止写入**：冲突是"用户还没做完的决定"，这时再合进一笔，等于把"用户手改版"和"模型新版"混成一份，谁覆盖谁没有答案。
- 应用前校验磁盘哈希：不符则转 `conflict`，不写入；用户只能「强制覆盖」或「拒绝」。
- **拒绝不动读取登记**：模型可能刚读到暂存文本，把磁盘哈希写进去等于假装它读过磁盘，下次会覆盖没见过的内容。应用成功则必须更新。
- 用户只能接受或拒绝整份改动，不能编辑暂存内容。
- 没有"关掉暂存"这个选项：`card` 模式的描述写入一律先暂存（ADR-046）。

## 11. 世界书记忆为什么"不生效"

**写进文件 ≠ 会生效。** ST 只扫描在扫描范围内的书：角色自带、聊天级绑定、世界书面板里手动勾选。前两条之外的书写进去，条目只是躺在文件里——插件记得再准也永远想不起来。

- `selected_world_info` 没有公开 API，判定只能读世界书面板的 DOM。三态：会被扫描 / 不会 / 判断不了（面板没渲染，按"已激活"处理，宁可漏报不误报）。
- **不自动把书加进激活列表**（ADR-021）。只把状态说清楚：`lore_list` 的 note 前加一句、写入返回的 note 换成"已写入，但这本书当前没有激活"、面板落点段转警告并写明去哪勾。
- 新建条目必须**显式**写空的触发列表。它表示"所有生成类型都参与"，缺这个字段的条目在部分生成类型下会静默不生效——不是报错，是根本不进上下文。

### 11.1 工具返回只说事实

不解释原因、不替模型组织台词——「为什么不行」「你该怎么对用户说」是模型自己对用户讲的话，工具返回值替它决定就变成了台词注入。

分界看**动作归谁**：模型自己该对数据做的动作（"考虑合并重复条目""先读一次"）可以写；要用户去做的事（"请提醒用户勾选"）以及"为什么这样"的解释，都不写。

## 12. 角色描述写入

落点由 `descStorage` 决定。两路共享：长度按**写入后的总长度**判断，不看本次增量；超硬上限拒绝，hint 只陈述事实并给一句可行的下一步（精简、拆条、改用局部替换）。软提醒只用于压缩面板，不进任何工具返回。

- `card`：先暂存成 patch，用户确认后才写 `description`；落盘后同步本地角色对象，若角色编辑面板开着且输入框未聚焦，一并同步其文本框——不刷新会让用户以为没写进去。追加语义是"当前文本 + 空行 + 新段"，当前为空则不补空行。
- `worldbook`：只写条目正文，并校正常驻 / 启用标志；标题、关键词、位置、顺序一律保持用户在编辑器里调过的样子。不碰角色卡、不写描述快照；写入前压一条世界书快照，撤销复用面板的「已写入」。

## 13. 用户看到什么

| 层 | 内容 |
|---|---|
| 徽章 | 输入框左侧的固定尺寸图标，只开关面板；颜色表示模式状态，有未处理的改动时带计数，不可用时置灰 |
| 聊天流 | 当轮只有一行纯文本日志，不留大块 HTML |
| 面板 | 模式（两个开关）、待确认（patch）、已写入（世界书快照，默认收起，展开只读、带恢复） |

- 按钮按**落点**命名，避免"刷新 / 重写 / 关闭"各指什么说不清（ADR-029）。
- patch 的 diff 默认折叠未改动行，只展开差异段。**中文描述常常整段一行**，不按句读切开就是"改一个字 = 整段删 + 整段增"，折叠也会失去意义。
- 「已写入」每条只读，唯一动作是恢复；恢复前弹确认，恢复后作废该条目的读取登记。展开状态不持久化。
- 面板收起后只留一行摘要，有新 patch 时自动展开。
- 设置页诊断：先问"环境支不支持工具"，不支持时才细分原因并各给一句"去哪改"。

### 13.1 工具日志

两个时机：**当轮压缩**——工具调用完成时把该条消息改写成一行纯文本（长字符串只留长度、数组只留条数）；**下一轮清理**——用户发下一条消息时删掉更早消息的工具调用记录，让 ST 的过滤条件把它们排除出上下文，`mes` 保留、继续显示。

两步都只处理**全部由 Thrive 工具构成**的消息，混合了其他扩展调用的消息原样留给 ST（ADR-013）。

## 14. 失败模式

| 现象 | 处理 |
|---|---|
| 后端不支持 tools / 函数调用未开 | 徽章置灰；设置页指出具体要改哪一项 |
| 后处理模式会移除工具消息 | 指向带 `_tools` 后缀的等效版本 |
| 可写书未激活 | 照常读写；工具侧只说"没有激活"，完整解释留给面板 |
| 模型不调工具 | 只在工具描述里给判断标准，不主动催促 |
| 模型写错目标 | 按错误码拒绝（`RESERVED_ENTRY` / `NOT_FOUND` / `NO_BOOK`），不代它改道 |
| 递归轮数耗尽 | ST 自行停止，插件不额外处理 |
| 世界书被用户手改 | 下次写入 `STALE_READ` |
| 消息被删 / 编辑 | 不回滚任何写入 |

## 15. 已知限制

1. 多标签页同时打开同一聊天时，后写的状态覆盖先写的，patch 可能丢失。
3. 世界书没有 patch，误写只能靠快照或手动编辑。
4. 关闭插件后，已写入的世界书与角色描述继续生效。
5. 提示词拖到分界线上方后，每次开关模式都会让 system 前缀重新 prefill；放尾部则只影响末尾。工具常驻只能保住工具定义那一段。
6. 每次工具日志清理会在历史中间段产生一次缓存断点。

## 16. 压缩面板

"内容太长"不再由模型自己处理（ADR-040）。软提醒只回答一个问题：**哪些内容值得压**；压不压、压到多少由用户决定。

- 形态：贴窗口左边的常驻侧栏，不可拖动。一个既挡在中间、又拖不动的窗口最难受，所以位置写死——位置可预期，关掉即还原。不加遮罩：改一段正文时经常要抬头看聊天区。
- 谁能进列表：角色描述（超软提醒，取当前模式下**实际那份**）、世界书条目（超软提醒且书已在设置里选中）。停用的条目不列——它不进上下文，压它没有意义。
- **待确认的 patch 不算**：它还没进过 prompt，压它等于压一份不存在的正文。有未处理改动时面板多一句说明，统计仍按盘上那份算。
- 排序：描述永远第一，其余按超出软提醒的幅度从大到小。世界书读不到（没选书 / 书被删）不算失败：保留描述那一条，原因写在列表上方。
- 入口只有面板标题栏右端一颗图标按钮，常驻、有条目时高亮并挂角标；**只有新冒出来的条目**才闪一下。两个面板都关着时弹一句 toast。首次扫描不算"新增"。
- 手动编辑：逐行就地改，同一时刻只开一个编辑框；保存时校验非空且不超硬上限——不是限制用户，而是防止"压完还是超长"，下次模型写入照样被拒。写世界书只动正文；写描述前若还有未处理 patch 直接拒绝。两条路径都**作废模型的读取登记**。
- 智能压缩目前是占位：入口、多选、提示词拼接都已落位，差调模型、结果预览、逐条确认写回三件事。
- 扫描是异步的，结果缓存成快照供界面同步读取；触发点全部去抖，并发扫描只让最后一次的结果落地。

## 17. 依赖的 ST 行为

不记行号——源码可搜。这些是会影响设计的**行为**：

| 行为 | 影响 |
|---|---|
| 注册的工具表为空时，请求体里连 `tools` 键都没有 | 关闭态才能做到"与原生一致" |
| 工具调用后自动续生成，有递归上限 | 一轮内可能有多笔写入，自写登记必须扛得住 |
| `stealth` 调用会吞掉正文 | 用 `stealth: false`，工具结果要能被用户看见 |
| 尾部注入不替换宏、头部替换 | 只能由插件自己替换（ADR-001） |
| `IN_PROMPT` 的扩展提示词被插在 `main` 之后，不是整个 system 区末尾 | 分界线上方只能保证"在 main 之后、其余预设之前" |
| 编辑器持有的是快照而非引用 | 写入后必须刷新编辑器（ADR-026） |
| 条目模板含空触发字段的语义 | 新建条目必须显式写（§11） |
