# Spec · Thrive 学习模式

适用于 SillyTavern 1.19.0（2026-09-14）

> **本文件只写"读代码看不出来的东西"**：为什么这样做、什么不许做、用户看到什么。
> 默认提示词、设置项与默认值、工具参数与返回字段、错误码清单、条目模板字段、各类常量上限——
> 一律只在源码里存在一份，这里不抄第二份。抄了就会漂。

---

## 1. 范围

**做**：在单人一对一对话中，让模型把对话里值得长期保留的信息写进世界书与角色描述。写入发生在一场**独立会话**里（ADR-050），所以开关只决定"要不要自动学"，聊天请求本身与原生完全一致。

**不做**：群聊；非线性对话的回滚（消息编辑、删除、回退后不做任何自动修正）；删除或停用世界书条目；自动创建世界书；任何文件系统、网络、设置类操作；知识索引、向量检索、摘要压缩这类"记忆系统"。

## 2. 术语

| 词 | 含义 |
|---|---|
| 学习模式 | 对话级**唯一**开关。开着就按判据自动学；关着仍可手动学一次 |
| 学习会话 | 一场一次性内部会话：自带预设、自带消息栈、自带工具，不碰当前聊天（ADR-049） |
| 预设 | 提示词卡片按 `promptOrder` 排成的一列消息，编译后就是学习会话的 system / user / assistant 段。里面放的是**通用提示词** |
| 目标内容 | 预设里的两条：**描述行**（可改可删的一句引子）+ **注入位**（没有正文，内容由运行时给：学习 = 当前对话记录合并成的一条消息；教授 = 用户写的那段话） |
| 教授 | 手动触发的一种：目标内容换成用户写的一段话（可附图），与当前对话无关，也不推进学习进度（ADR-051） |
| 通用提示词 | 每一场都成立的东西：这场会话里你是谁、擅长什么、按什么标准判断。是列表里的第一张卡（`rules`），学习 / 压缩共用 |
| 特化提示词 | 只在那一场成立的东西：产出方式、写到哪、怎么写、这一次的要求。就是开场白（学习 / 压缩各一段） |
| 开场白 | 预设之后发出的第一条 User 消息，内容就是那一种任务的**特化提示词**，在提示词编辑器的折叠块里编辑 |
| 可写书 | 世界书工具唯一的读写目标，按对话选。统一描述模式下固定为角色同名书 |
| 虚拟世界书 | 真实世界书的一层缓冲区（ADR-047）。工具读写它，真实世界书等用户点保存才变 |
| patch | 角色描述的"磁盘值 vs 暂存值"的单份差异，等待用户接受或拒绝（`card` 模式恒有，ADR-046） |
| 快照 | 直写前的上一版内容，仅供手动恢复。带 `layer`，说明它记的是缓冲区还是真实世界书 |

## 3. 结构与界面分工

```
学习模式(对话级) ─┬─ 判据命中（每 N 条 / 关键词）
                  └─ 手动「立刻学一次」
                          │
                          ▼
                一场一次性会话（不碰当前聊天）
   预设（通用提示词 → 描述行 → 自建卡 → 注入位）+ 开场白（特化提示词）
                          │
        ┌─────────────────┴─────────────────┐
   世界书工具（那本书）              角色描述工具（卡 / 条目）
   即时写入                          暂存为 patch / 直接写条目
```

聊天侧不注册工具、不注入提示词、不写工具日志：请求体与原生逐字节一致。学习要的东西全在那场会话里。

界面按**作用域**分两处，不按功能模块分（ADR-043）。规则只有一句：**换一场对话，它该不该变？**

- **浮动面板**：这一场的全部东西——学习模式开关、立刻学一次 / 停止、描述存哪儿、可写书、待确认改动、写入记录。
- **扩展设置页**：跨对话一致的设置——新对话默认、自动学习判据、数值上限、提示词入口、面板外观。这一页不随对话变化（ADR-045）。
- **独立窗口**：东西多到一屏放不下的两块——提示词编辑器、压缩侧栏、虚拟世界书。它们从面板或设置页的按钮进入，本身不占位置。

两处界面都不直接互相调用：谁要在状态变化时刷自己，把刷新函数登记到 `ui/refresh.js` 的分区表里（ADR-030）。

## 4. 状态

两条存储线：跨对话设置走 `extension_settings.thrive`，对话级状态走 `chat_metadata.thrive`。键名、类型、默认值只在 `src/store.js` 维护。需要代码之外才知道的约定：

- 提示词正文与开场白都用**空串表示"用默认文本"**，不是存快照。这样默认文本随版本更新、老用户也能拿到新版；「恢复默认」就是清回空串。
- 学习状态（基线、上一轮用户消息哈希、上次结果）挂在对话上；"有没有一场在跑"是**进程级**标记，不是存储值——它只描述此刻，不该被刷新页面继承。
- 排队队列同样**只活在内存里**（ADR-052）：它描述的是"马上还要学一次"，刷新页面就重放没有意义，反而可能把旧内容当成新任务再写一遍。
- `connectionProfile` 是**全局**设置，不是对话级：换一个角色聊天不该顺手换掉学习用的后端。
- 编辑器里改了立刻生效、落盘防抖。
- 快照记录**一条数据两用**：既是恢复用的快照，又是面板「已写入」的一行（ADR-016）。老聊天里缺字段的记录读时兼容，不做迁移脚本。
- 虚拟世界书也挂在 `chat_metadata.thrive.draft` 上：换一场对话就换一块缓冲区。它是**整本书的副本**，所以聊天文件会比以前大（ADR-047 的代价）。
- 旧设置会做一次性迁移（v0.33）：`blockText` / `blockCommon` / `learnPrompt` → `sessionRules`、`passiveInterval` → `learnInterval`、`passiveKeywords` → `learnKeywords`、两个旧开关取或进 `enabledByDefault`、`compactPrompt` → `compactTask`；"自动注入 / 工具常驻 / 工具指令 / 日志截断"这些键直接删掉。
- v0.37 再分层（ADR-054）：`learningUserMessage` / `compactUserMessage` / `learnPrompt` 一律并进 `learningTask` / `compactTask`（旧文字讲的都是流程，属于特化内容）；v0.36 的 `sessionRules` 也搬进 `learningTask` 并把通用提示词卡插到顺序表最前，判据是顺序表里没有 `rules`（它不可删）。

## 5. 开关与模块

- 学习模式是**对话级**开关；新对话取 `enabledByDefault`。它是**唯一**的开关，没有主动 / 被动之分。
- 入口：输入框左侧徽章（开面板）、面板里那颗开关、`/thrive on|off`。手动学一次另有面板按钮与 `/thrive learn`。
- 关闭时不向聊天流插入任何消息；切换也不改变聊天请求（本来就没有插件内容在里面）。
- **没有模块开关**（ADR-046）：世界书工具常在；角色描述工具两种存储模式都有，只是落点不同。
- 没选可写书时世界书工具**不可用**（`isToolAvailable` 返回 false），面板里写明"没选可写书"。描述工具不受影响。
- 读范围只有一本：能读到的条目就是能改的那一条。

### 5.1 自动学习

开关只是"要不要自动学"，怎么触发由两条**全局**判据决定（设置页「自动学习」组）。任一命中就在**角色回复完之后**起一场会话。

| 项 | 规定 |
|---|---|
| 判据 | ① 距上次学习累计 N 条可见消息；② 最近一轮 User / Assistant 消息命中关键词。两者是 **or** |
| 计数口径 | 只数非 `is_system` 的消息，一问一答算 2 条 |
| 关键词口径 | 只扫最近一条 User 与最近一条 Assistant 的正文；大小写不敏感、子串匹配；世界书 / 作者注释 / 预设不参与 |
| 评估时机 | 只在 `MESSAGE_RECEIVED` 之后。学习是独立会话，不必抢在生成之前；放在回复之后既不与聊天抢后端，也保证这一轮两边都已落进记录 |
| 触发 | 直接起会话（不再"挂记号等下一轮"）。已经有会话在跑时**排队**，不丢也不并（§18） |
| 去重 | 记下这一轮用户消息的哈希；AI 把关键词复述一遍不会连着学两遍 |
| 落点 | 判据是**全局**设置（设置页）；开关与进度是**对话级**（面板） |

- 面板与徽章只**读**判据来算"还差几条"，一条都没配时指路到设置页，并说明"只有手动「立刻学一次」会触发"。
- 手动入口有两个：**立刻学一次**（学这段对话）与**教授**（学你写的那段话 + 图）。两者都不受开关与判据限制：用户明确要求就给他一场。
- 判据两项都空着时组内出小字说明这是空转。那是没配，不是错误，所以不用警告色。
- **切换对话会中止正在跑的那一场，并清空队列**：工具写的是"当前对话"的 `chat_metadata`（可写书、读取登记），跑到一半换场就可能把内容写进另一个角色；排队的那几场同理，它们写的是上一个对话的书。

### 5.2 工具的可用性

聊天请求里没有 `tools`，所以可用性不是"注册 / 不注册"，而是"此刻有没有一场学习在跑"：`isToolAvailable(name)` 先问 `isLearningActive()`，再问具体前置条件（世界书工具还需要一本可写书）。

- 工具定义在 `src/tools.js` 是一张表，由 `session-tools.js` 包装成会话私有工具；不进 `ToolManager`，任何请求都看不见它们。
- 会话外被调用（理论上不会发生）会返回 `TOOL_UNAVAILABLE`。
- 不再有"工具常驻"开关，也没有"工具指令"那段提示词：两者存在的理由（`tools` 数组会变、工具会被误调）随"工具不进聊天请求"一起消失（ADR-050）。

### 5.3 角色描述的存储模式

`descStorage`（对话级，ADR-042）：`card`（默认，老机制）/ `worldbook`（统一使用世界书）。两套机制并存，切回即恢复，不做一次性迁移。

| 项 | `card` | `worldbook` |
|---|---|---|
| 正文在哪 | 角色卡 `description` | 与角色同名那本世界书的 `【角色描述】` 条目 |
| 怎么进上下文 | ST 原生角色卡注入 | 世界书常驻条目 |
| 暂存 / diff | 有 | 无 |
| 撤销 | 描述快照单槽 | 世界书快照（面板「已写入 → 恢复写入前」） |

- **切换不做内容迁移**：条目从空白开始，角色卡上原有的文字既不搬走也不清空。卡上残留的描述仍由 ST 注入，但面板**不为此出警告**（ADR-046）：用户改的不是这一处、也不知道该怎么处理，说一句"卡上还留着 N 字"只会让人一头雾水。插件自己不去改用户的卡。
- `worldbook` 模式下**可写书固定为角色同名书**：描述就在那本书里，允许另选一本会让"描述写哪儿"出现两个答案。面板把下拉置灰并显示出真正的目标书。
- 例外：角色改过名、描述此前已落在绑定书里时，仍认那本旧书（否则改名等于再建一本空书）。此时"可写书"按现名给，两条提示各自写出书名——不静默分叉，也不自动搬家。
- `desc_*` 四个工具的名字与参数不变，只换落点；`lore_*` 六个工具**看不到也改不了**这条条目（`RESERVED_ENTRY`）。
- 条目必须常驻且启用：每次写入都校正常驻与停用标志。这两个字段是"描述"这个语义的基础，被用户或别的插件改掉之后必须掰回来。
- 切回 `card` 时把条目停用（内容保留），否则两处内容会同时进上下文。
- 书怎么选，顺序固定：绑定书里已有该条目 → 与角色同名的书 → 首次写入时新建同名书。
- **不自动**改动世界书的激活列表，书没被扫描到时面板转警告并指出去哪勾（见 §11）。
- 切换时有未决 patch → **拒绝切换**，先让用户在面板里写入或丢弃。

## 6. 提示词

提示词在这里的含义变了（ADR-050）：它不再"注入到聊天请求的某个位置"，而是**一场学习会话的预设**。

### 6.1 卡片、顺序与自建提示词

设置页「提示词」折叠块只留入口：一行摘要和「打开编辑器」按钮。列表本身搬进了独立窗口（ADR-048），因为一屏要同时放名称、角色、状态、开关，塞在设置页里只能层层折叠。

列表里放的是**通用提示词**：每一场都成立的定位（ADR-054）。顺序存在 `promptOrder`，卡片分两类：

- **内置卡**三条：
  - `rules` **通用提示词**：这一场里你是谁、擅长什么、按什么标准判断。默认「你是一名长期记忆整理专家……」，可改、可停用，**不可删**（停用就够表达"我不要这段"）。不含任何流程——产出方式 / 写到哪 / 怎么写都在开场白里。
  - `targetDesc` **描述行**：默认「以下是目标内容：」，正文可改、可停用、可从列表里移除（正文留着，「默认顺序」能拿回来）。
  - `target` **注入位**：没有正文，运行时填真实内容。不可改、不可停用、不可删，位置固定最后。
- **自建卡**：用户自己写的提示词，存在 `customPrompts`（`{ id, name, content, role, enabled }`），id 形如 `cp_xxxx`。

`normalizeOrder` 保证顺序表永远合法：`target` 一定存在且一定在最后，自建卡插在它之前，认不出的 id 丢掉，缺的补上。**`targetDesc` 不会被自动补回**——删了就是删了，想回来走「默认顺序」。默认顺序是 `[rules, targetDesc, target]`。

- 内置卡：描述行可移除，通用提示词与注入位不可移除；自建卡可改名、改正文、改角色、停用、删除。
- 停用（`disabledCards` / `customPrompts[].enabled`）只影响预设，正文留着。
- **没有"这一轮生不生效"**：预设是"这一场会话长什么样"，触发就整份发出去，不触发就什么都不发。所以界面上没有「未生效」角标这东西。
- 拼接规则（`buildPreset`）：
  - 描述行与注入位**挨着时并成一条消息**（`描述行 + 空行 + 内容`），角色用描述行的。
  - 描述行被停用或已移除时，注入位**单独成一条** System 消息，内容一个字不少。
  - 目标内容为空时描述行也不发（只剩一句"以下是目标内容："比不出现更糟）。


### 6.2 编辑器（独立窗口）

第四个独立窗口（前三个：浮动面板、压缩侧栏、虚拟世界书）。标题栏可拖，Esc 关闭；正在编辑时 Esc 先取消编辑。

- 一行 = 抓手 + 名称 + 角色 chip + 字数 + 编辑按钮 + 尾部滑块开关。注入位那一行没有抓手（换一个锁图标）也没有开关。
- 行上不放正文预览，也不放角色下拉和删除按钮。这两样都挪进了展开后的编辑区，卡片右侧只剩「编辑 + 滑块」两列，纵向才对得齐。
- 行上只呈现用户自己设的东西：启用 → 正常亮度 + 强调色左边线，停用 → 整行压暗 + 虚线边框（`data-enabled`），正文都留着。注入位用虚线边框：它无所谓启用，它一定在。
- 行尾的说明是字数；注入位那一行写「运行时注入 · 内容随触发生成」——那是卡的属性，不是当轮判定。
- 最上面那张「通用提示词」卡讲的是这一场里模型是谁；它的说明行写"通用提示词：学习与压缩都带上，讲的是这一场里你是谁"。
- 编辑区：名称（仅自建卡可改）+ 角色下拉 + 字数 + 正文（10 行，右上角全屏按钮）+ 提示 + 恢复默认 / 删除 / 取消 / 保存。
- 「编辑」按钮本身是开关：再点一次收起。有未保存改动时先问一句「收起会丢掉刚才的改动」。
- 角色下拉提供系统 / 用户 / 助手，就是这条消息在会话里的 role。改角色只就地刷 chip 与亮度，不整块重绘——否则输入框和光标都会被抽掉。
- 正文框挂 `data-macros`（`data-macros-autocomplete="always"`），宏补全交给 ST 自己的 `MacroAutoComplete`：它用 MutationObserver 盯着新插入的输入框，所以标记写在模板里就够。
- 全屏编辑同样走 ST 的放大编辑：`callGenericPopup(POPUP_TYPE.TEXT, { wide, large })`，Ctrl+Enter 完成、Esc 取消；取消不写回草稿。
- 补全浮层是 ST 自己挂在 body 上的 DOM，靠输入框 `blur` 收起。整块重绘会把输入框节点直接换掉、页面失焦时 `blur` 甚至不派发，两种情况浮层都会悬在窗口上，所以换 DOM 与关弹窗前主动失焦，再兜底清一次 `body > .autoComplete-wrap` / `.autoComplete-detailsWrap`。
- 新增会立刻建一张空卡并聚焦名称，取消则回滚删除——不留半成品；空着就关窗口也会把它收掉。
- 删除前弹确认框，文案里写明名字，并且**区分两种删除**：自建卡「删除」（正文一起没），描述行「拿掉」（正文留着）。用 `callGenericPopup` + `POPUP_TYPE.CONFIRM`，不用已废弃的 `#dialogue_popup`——中文按钮在那套样式里会被压成竖排。
- 列表下面是两个折叠块（原生 `<details>`，开合状态存在内存里，重绘后还原）：
  - **会话开场白**：**学习时发送** / **压缩时发送** 两行，展开后是正文框 + 恢复默认 / 取消 / 保存，字数写"空 · 用默认文本"。它们没有抓手、没有开关、没有角色——不参与排序。块首一行小字写明分工：列表里的是通用提示词（每场都带），这里是特化提示词（只在那一种任务里发出）。
  - **工具列表**：`getToolDefs()` 的十个工具，一行两个卡片，每张写显示名、真实工具名、一句用途、激活状态。**只读**：工具是插件的实现，不开放开关。
- 卡片编辑与开场白编辑**互斥**（同一时刻只展开一处）：它们回答的都是"这一场会话说什么"，同时改没有意义。
- 窗口内部状态（草稿、滚动位置、拖动中、展开的编辑区、折叠块）与刷新登记表配合：拖动时不重绘；任何一处展开着时不用非强制重绘（ADR-030）。窗口本来就开着时重进只重画，不丢草稿。


### 6.3 宏展开

预设编译时逐段 `substituteParams`，所以 `{{char}}` / `{{user}}` / `{{setvar::名::值}}` / `{{getvar::名}}` 都能用。

- 宏替换是**副作用式**的（`setvar` 会写进 ST 的变量表），所以必须**按顺序逐段替换**：前一段 `setvar` 的值后一段才读得到。
- 某一段替换失败（宏写错、变量不存在）时按**原文**发出，不整份放弃——一句坏宏不该让整场学习失败。
- 空段（停用、正文为空白）在编译时跳过，不会产生空消息。

### 6.4 有损导入 ST 预设

「导入预设」是一个来源菜单，两种入口读到的都是同一份 JSON 形状：

- **从文件…**：用户自己挑一份预设 `.json`。
- **SillyTavern 预设 →**：直接列 ST 现有的预设（`getPresetManager('openai').getPresetList()`，只列带正文的），省掉找文件那一步。

按"能变成消息的部分"搬过来：

| 处理 | 内容 |
| --- | --- |
| 保留 | 名称、正文、角色、启用状态（`prompt_order` 里的 enabled 优先于 `prompts[].enabled`）、`prompt_order` 里的相对次序 |
| 忽略 | 触发器（`injection_trigger`）、`injection_order`、`injection_position`、`injection_depth`、`system_prompt` 标记 |
| 跳过并计数 | `marker: true` 的标记块（世界书 / 角色卡 / 作者注释等，没有正文）、空正文、重复 identifier |
| 不改 | 目标内容的两条内置卡原样保留 |

- 新顺序固定是 `[通用提示词, ...导入的卡, 描述行, 注入位]`：通用提示词要先读到，导入的条目是规则排在材料前面，注入位是待处理的材料，紧挨着开场白。
- 导入是**整批替换**：先清空 `customPrompts`、`disabledCards`、`promptRoles`，再按上面的顺序重建。
- 落盘前先弹确认框，把"导入几条、跳过几条为什么、几条核心系统提示词可能重复交代"逐项写清楚。
- 失败只报一句人话（不是 JSON / 没有 prompts / 没有可导入的条目 / 不像预设），不抛栈。

### 6.5 开场白（特化提示词）

开场白是**特化提示词**：只属于那一种任务，讲这一场具体怎么干（ADR-054）。

| 设置键 | 内容 | 谁用 |
|---|---|---|
| `learningTask` | 这一次要它做什么 + 产出方式 / 写到哪里 / 怎么写 | 学习 |
| `compactTask` | 把这段压短、写回原来那一条 + 它的产出方式与写法 | 压缩 |

- 发出去的那条 User 消息就是本段整条，不与别的段落拼接。通用提示词（`sessionRules`）不在这里——它是列表里那张卡的正文，作为预设的第一条消息先发（§6.1）。
- 两段都是空串 = 用默认；写回等于默认文本时也存回空串。
- 学习会话启动时读它作为第一条 User 消息（`runSession` 的 `userMessage`）；整段没有任何字符时这场会话直接失败（`SESSION_NO_MESSAGE`），因为模型不知道要干什么。
- 默认文本刻意写成"任务 + 流程"三段式（产出方式 / 写到哪里 / 怎么写），因为这三样在不同任务里不一样；**不写** {{char}} / {{user}} 的指代问题——新会话里模型是第三方整理者，不是聊天里的角色。
- 压缩还没接线，但它的提示词已经可以编辑——将来压缩复用同一条链路，换的只是开场白与目标内容。

### 6.6 教授的目标内容

教授复用整条链路，只有目标来源不同：`buildTeachTarget()` 把用户写的那段话（可带图）整理成目标内容，其余交给 `buildPreset(settings, { target })`。

| 项 | 规定 |
|---|---|
| 正文 | 去首尾空白后最多 6000 字（`TEACH_MAX_CHARS`），超出截断；只有图没有字时用一句"材料就是下面这条消息里的图片"占位 |
| 图片 | 最多 4 张（`TEACH_MAX_IMAGES`）；只收 data URL，非 data URL 一律丢弃 |
| 粘贴 | 正文直接粘贴；剪贴板里的图片走与「图片」按钮同一条通道（同样受 4 张 / 12 MB 限制，超 700 KB 或边长 >1400 px 先缩）。剪贴板同时有图有字时**只接图并拦掉文字插入**——那段字多半是文件名或网址 |
| 图片走哪条消息 | **不进预设**（预设是纯文本 run 列表），挂在这一场会话的**开场白**那条 User 消息上，`content` 变成 `[{type:'text'},{type:'image_url'}]` 块数组 |
| 目标内容里提图 | 有图时正文末尾补一句"附了 N 张图，在下面这条消息里"，否则模型只看到一段文字，不知道还有图 |
| 对话状态 | **一个字都不改**：不调 `beginLearn`，基线、`lastHash` 原样保留。教一次不代表这段聊天被学过了 |
| 会话结果 | 照常写 `lastRun`，`reason = 'teach'`；面板与徽章说"上次教授…"而不是"上次学习…" |
| 协议约束 | `assertProtocol` 只允许 **user** 消息的 `content` 是块数组，块只能是 text / image_url，image_url 必须是 data URL |
| 预算估算 | 图片不按 base64 长度算 token：先按固定占位串算文本字节，再每张补 `IMAGE_TOKENS`（1100） |

## 7. 工具契约

十个工具，名字固定。参数 schema、描述文案、返回字段以 `src/tools.js` 为准；它们只在一场学习会话里可用，不进聊天请求的 `tools`（§5.2）。

命名是 `<目标>_<动词>`，动词只有 read / list / add / append / replace / rewrite。读一律叫 `read`——同一个动作两种叫法，模型要多花一步去分辨它们是不是一回事（ADR-032）。

| 工具 | 作用 | 写入前置 |
|---|---|---|
| `lore_list` | 目录：已启用条目的标题 | — |
| `lore_read` | 单条正文 / 正则片段 | — |
| `lore_add` | 新建条目 | 目录读过 |
| `lore_append` | 追加正文、追加关键词 | 见过这条标题 |
| `lore_replace` | 正则替换正文片段 | 同一 pattern 预读命中 |
| `lore_rewrite` | 整段替换正文 | 该条全文已读 |
| `desc_read` | 描述全文 / 正则片段 | — |
| `desc_append` | 末尾追加一段 | 读过描述 |
| `desc_replace` | 正则替换片段 | 同一 pattern 预读命中 |
| `desc_rewrite` | 整段重写 | 全文已读 |

模型依赖、但代码里不显眼的三条：

- **错误返回统一形状** `{ ok: false, error, hint }`。`hint` 只说事实与下一步动作。
- **错误码清单以 `src/diagnostics.js` 为唯一来源**，文档不列。
- **两个 `rewrite` 都只改正文**：标题是定位键、关键词是触发方式，压缩正文时一律保留原值。要加关键词走 `append`，要改标题只能由用户在世界书编辑器里改。

## 8. 读写一致性

**写入前置分四级**，读得越少，能写的越少（ADR-007）：目录 → `add`；见过标题 → `append`；同 pattern 预读命中 → `replace`；读过全文 → `rewrite`。

- 分级的理由：只看过标题就允许整段覆盖，"先读后写"就只是口号；反过来，追加与替换由插件在盘上的完整正文上做增量，模型手里那半截文本冲不掉后半段，所以不需要全文。
- **检查顺序不可调**：学习模式是否开着 → 目标是否可用 → 前置级别够不够 → 其余校验。顺序本身就是给模型的反馈：先说"现在不能写"比说"你没读过"有用。
- **局部编辑不做 `STALE_READ` 阻断**；只有整段重写要求读取时的哈希与当前一致。
- **自写登记**：写入成功后把新内容哈希写回，并作废该目标上所有 pattern 预读——正文变了，之前看清的命中位置就不再成立。不登记的话，同一次回复里的第二笔写入会被自己挡住。
- 全文读取被截断时**不登记全文**：拿半截文本去重写会冲掉后半段。

### 8.1 虚拟世界书（缓冲区）

真实的文件写入是这三件事之一：改盘上文件、让 ST 的世界书缓存失效、让请求头部那段内容变（前缀缓存从那里整段作废）。这三样都只在"用户已经同意"时才值得付，所以写往世界书的动作先落进一层缓冲区（ADR-047）。

- **路由只有两处**：`targets.loadBook`（读）与 `targets.persistBook`（写）。这两个函数之外，没有任何模块知道自己操作的是缓冲区还是磁盘——四级守卫、长度上限、关键词截断、条目模板在两层之间完全一致。
- **缓冲区什么时候开**：第一次真正要写的时刻（守卫全过、`data` 还是改动前的那一份）。被 `READ_REQUIRED` 之类挡住的写入不留缓冲区；写入被拒（超长、空正文）时如果一条都没改成，缓冲区连同它的存在一起撤掉——一块空壳会让工具看不见之后在编辑器里做的改动。
- **读优先缓冲区**：写进缓冲区之后，读到的、目录列出的、压缩面板统计的都是缓冲区。所以同一轮里"追加 → 再追加"相互叠加，跟写真的世界书一样。
- **缓冲区只属于一本书**：它开在哪本书上就管哪本。换可写书时若有未保存的改动会被拦住；空缓冲区直接收掉。工具写另一本书时返回 `DRAFT_BOOK`，不跨书写（否则"保存"会把 A 的内容写进 B）。
- **保存 = 整本替换**，只有用户能触发。开出来那一刻会记一份指纹（只算工具会改的字段，按 uid 排序）；保存时指纹不符说明磁盘被别处改过，第一次拒绝、界面换成"会覆盖"的确认文案再问一次。
- **保存之后逐条补快照**（`layer: disk`），缓冲区那层的记录同时收掉：它们指向的那块缓冲区已经不存在了。丢弃同理，一个快照都不补。
- **快照分层恢复**：`draft` 只能恢复到缓冲区，`disk` 只能恢复到真实世界书。跨层一律拒绝（`DRAFT_GONE` / `DRAFT_ACTIVE`）——拿缓冲区里的 `before` 覆盖磁盘，等于凭空造出一份没人同意过的内容。
- **进上下文要等保存**：ST 只扫磁盘上的书。缓冲区里的内容模型读得到（走插件），但角色这一轮不会因此记起新设定。这是"先看再落盘"的直接后果。

## 9. 权限

| 目标 | 可读 | 可写 |
|---|---|---|
| 世界书 | 可写书（`lore_list` / `lore_read` 都只这一本） | 仅可写书，且只写进它的缓冲区 |
| 角色描述 | 当前落点的那份（角色卡或保留条目） | 同左；世界书那一路同样先落缓冲区 |

读范围收成一本是有意的（ADR-046）：读到一条改不了的内容，模型无法判断它算"已经记在别处"还是"还不存在"，两个答案都会让它做错事。

"只写进缓冲区"是模型侧的天花板：**把缓冲区落到真实世界书不是工具能力**，它只有一颗用户能点的按钮（ADR-047）。缓冲区里也不提供删除——`created` 的反向操作仍然只发生在用户点「撤销新建」时（ADR-011 只约束模型）。

`【角色描述】` 不属于世界书条目的权限范围：目录不列它，`lore_*` 按标题一律拒绝；反过来 `desc_*` 也不会碰任何普通条目。

**禁止**：`personality`、`scenario`、`first_mes`、`mes_example`、角色名、头像、预设、正则、任何设置、任何文件。目标类型与模块不符时直接拒绝，不降级。

**关闭 = 工具从请求里消失**，而不是"注册了再拒绝"。模型看不见不该用的工具，才不会反复试。

## 10. patch（仅 `card` 模式）

统一使用世界书的模式没有 patch：描述直接写成一条条目，面板不提供 diff。

- 同一时刻最多一份 patch，状态只有 `pending` / `conflict` / `applied`。
- **合并基准是暂存值**：暂存期间再来一笔写入，以它为新基准继续合，磁盘那份不动。读取在暂存期间也返回暂存值——否则第二笔必然 `STALE_READ`。
- **冲突期间禁止写入**：冲突是"用户还没做完的决定"，这时再合进一笔，等于把"用户手改版"和"模型新版"混成一份，谁覆盖谁没有答案。
- 应用前校验磁盘哈希：不符则转 `conflict`，不写入；用户只能「强制覆盖」或「拒绝」。
- **拒绝不动读取登记**：模型可能刚读到暂存文本，把磁盘哈希写进去等于假装它读过磁盘，下次会覆盖没见过的内容。应用成功则必须更新。
- 用户只能接受或拒绝整份改动，不能编辑暂存内容。
- 没有"关掉暂存"这个选项：`card` 模式的描述写入一律先暂存（ADR-046）。

## 11. 世界书记忆为什么"不生效"

**写进文件 ≠ 会生效。** ST 只扫描在扫描范围内的书：角色自带、聊天级绑定、世界书面板里手动勾选。前两条之外的书写进去，条目只是躺在文件里——插件记得再准也永远想不起来。

- `selected_world_info` 没有公开 API，判定只能读世界书面板的 DOM。三态：会被扫描 / 不会 / 判断不了（面板没渲染，按"已激活"处理，宁可漏报不误报）。
- **不自动把书加进激活列表**（ADR-021）。只把状态说清楚：`lore_list` 的 note 前加一句、写入返回的 note 换成"已写入，但这本书当前没有激活"、面板落点段转警告并写明去哪勾。
- 新建条目必须**显式**写空的触发列表。它表示"所有生成类型都参与"，缺这个字段的条目在部分生成类型下会静默不生效——不是报错，是根本不进上下文。
- **缓冲区里的内容不算"写进文件"**：它连文件都还没到。ST 扫不到它，所以这一轮角色不会因为刚学到的三条设定而记住它们；保存之后才轮到上面那套扫描规则（ADR-047）。

### 11.1 工具返回只说事实

不解释原因、不替模型组织台词——「为什么不行」「你该怎么对用户说」是模型自己对用户讲的话，工具返回值替它决定就变成了台词注入。

分界看**动作归谁**：模型自己该对数据做的动作（"考虑合并重复条目""先读一次"）可以写；要用户去做的事（"请提醒用户勾选"）以及"为什么这样"的解释，都不写。

## 12. 角色描述写入

落点由 `descStorage` 决定。两路共享：长度按**写入后的总长度**判断，不看本次增量；超硬上限拒绝，hint 只陈述事实并给一句可行的下一步（精简、拆条、改用局部替换）。软提醒只用于压缩面板，不进任何工具返回。

- `card`：先暂存成 patch，用户确认后才写 `description`；落盘后同步本地角色对象，若角色编辑面板开着且输入框未聚焦，一并同步其文本框——不刷新会让用户以为没写进去。追加语义是"当前文本 + 空行 + 新段"，当前为空则不补空行。
- `worldbook`：只写条目正文，并校正常驻 / 启用标志；标题、关键词、位置、顺序一律保持用户在编辑器里调过的样子。不碰角色卡、不写描述快照；写入前压一条世界书快照，撤销复用面板的「已写入」。缓冲区开着时这一笔同样先落缓冲区——描述条目是那本书里的一条，没有理由例外。

## 13. 用户看到什么

| 层 | 内容 |
|---|---|
| 徽章 | 输入框左侧的固定尺寸图标，只开关面板；强调色 = 学习模式开着，呼吸 = 正在学，置灰 = 不可用；有未处理的改动时带计数 |
| 聊天流 | **什么都没有**。学习不在聊天里跑，聊天侧不留任何插件痕迹 |
| 面板 | 学习模式（一个开关 + 状态行 + 教授 / 立刻学一次，跑起来换成停止）→ 更多设置（落点）→ 待确认（patch）→ 已写入（世界书快照，默认收起）；标题栏两颗图标：虚拟世界书、压缩 |
| 面板·排队 | 有任务在等时，状态行后面多一颗描边小标签「排队 N」；按钮**不隐藏**——点了没反应比点了要等更让人困惑 |
| 教授窗口 | 独立窗口：一段正文框（可写宏、Ctrl+Enter 开始，可直接粘贴文字与图片）、至多 4 张缩略图、字符计数；关掉不丢草稿，「清空」才清 |
| 虚拟世界书窗口 | 独立窗口，只读：条目名、触发条件、正文 diff、保存 / 丢弃。未改动的条目默认收起 |
| 提示词窗口 | 独立窗口：通用提示词、目标内容的描述行与注入位、自建卡按顺序同列一表，启用/停用按整行亮暗区分，可增删改、改角色、拖动排序（注入位固定末尾）；列表下面是两个折叠块——会话开场白（学习 / 压缩各自的**特化**提示词）与工具列表（十个工具、只读）；正文框带宏补全与全屏编辑；有损导入 ST 预设 |

- 按钮按**落点**命名，避免"刷新 / 重写 / 关闭"各指什么说不清（ADR-029）。
- patch 的 diff 默认折叠未改动行，只展开差异段。**中文描述常常整段一行**，不按句读切开就是"改一个字 = 整段删 + 整段增"，折叠也会失去意义。
- 「已写入」每条只读，唯一动作是恢复；恢复前弹确认，恢复后作废该条目的读取登记。展开状态不持久化。属于缓冲区的记录带一个「缓冲区」标记，缓冲区一保存或丢弃就被收掉。
- 虚拟世界书的 diff 用与 patch 同一套行级算法（`src/diff.js`）：未改动行折叠，中文长句按句读切成段，否则改一个字就是"整段删 + 整段增"。
- 窗口只在浮动面板标题栏有一颗入口（书页图标 + 改动条数），不做自动弹出：它是"想起来看一眼"的东西，不像 patch 那样必须做决定才能继续。
- 面板收起后只留一行摘要，有新 patch 时自动展开。
- 设置页**没有**环境诊断块（ADR-052）：会话能不能跑，只有真发一次请求才知道；预判"工具不可用"会把本来能跑的学习挡住。

### 13.1 工具日志

**没有了**（ADR-050）。以前工具调用发生在聊天轮次里，所以要在 `mes` 里压成一行、还要在下一轮把旧日志移出上下文；现在工具调用在会话自己的消息栈里，从来不进聊天。

「已写入」仍然记世界书与描述的每一次写入——那是给人看的记录，不是给模型看上下文。

## 14. 失败模式

| 现象 | 处理 |
|---|---|
| 后端不支持 tools / 函数调用未开 | 徽章置灰，面板与设置页都指出具体要改哪一项；判据命中也不会起会话 |
| 回复形状不是 OpenAI（Claude / Gemini 原生） | `SESSION_PROVIDER_UNSUPPORTED`，不猜着解析 |
| 可写书未激活 | 照常读写；工具侧只说"没有激活"，完整解释留给面板 |
| 模型不调工具 | 视为正常结果（没有值得记的内容），摘要里明说"没有调用工具" |
| 模型写错目标 | 按错误码拒绝（`RESERVED_ENTRY` / `NOT_FOUND` / `NO_BOOK`），不代它改道 |
| 撞到轮数上限 | 算没跑完，摘要写"撞到轮数上限 · 结果可能不完整" |
| 预设为空（卡全停用了） | `SESSION_NO_PRESET`：不起会话，提示去启用至少一条 |
| 目标内容为空（没有可见消息） | `NO_TARGET`：不起会话 |
| 世界书被用户手改 | 下次写入 `STALE_READ` |
| 消息被删 / 编辑 | 不回滚任何写入 |
| 切换对话时正在学 | 直接中止（工具写的是"当前对话"的元数据） |

## 15. 已知限制

1. 多标签页同时打开同一聊天时，后写的状态覆盖先写的，patch 可能丢失。
2. 世界书没有 patch，误写只能靠快照或手动编辑。
3. 关闭插件后，已写入的世界书与角色描述继续生效。
4. 判据只在**角色回复之后**评估，所以"每 N 条"的触发点比字面晚半轮；第一次评估时基线还在对齐。
5. 结果只有摘要：会话不落盘、没有界面，能看到的只有"几次工具调用 / 几轮 / 有没有跑完"，以及世界书与描述里的实际变化。
6. 提示词只有一份：不做多预设的存储与切换，导入即整批替换当前自建集合（要留旧的先自己做备份）。导入是有损的，触发器、注入位置、标记块都不搬（§6.4）。
7. 学习会话只认 OpenAI 形状的回复；Claude / Gemini 原生连接下不能用。
8. 一场学习的体积大致是"预设 + 目标内容（上限可调）"，默认 6000 字的目标内容对长对话只是后半段——超出的部分会明说"更早的 N 条消息没有包含"。

## 16. 压缩面板

"内容太长"不再由模型自己处理（ADR-040）。软提醒只回答一个问题：**哪些内容值得压**；压不压、压到多少由用户决定。

- 形态：贴窗口左边的常驻侧栏，不可拖动。一个既挡在中间、又拖不动的窗口最难受，所以位置写死——位置可预期，关掉即还原。不加遮罩：改一段正文时经常要抬头看聊天区。
- 谁能进列表：角色描述（超软提醒，取当前模式下**实际那份**）、世界书条目（超软提醒且书已在设置里选中）。停用的条目不列——它不进上下文，压它没有意义。
- **待确认的 patch 不算**：它还没进过 prompt，压它等于压一份不存在的正文。有未处理改动时面板多一句说明，统计仍按盘上那份算。
- 排序：描述永远第一，其余按超出软提醒的幅度从大到小。世界书读不到（没选书 / 书被删）不算失败：保留描述那一条，原因写在列表上方。
- 入口只有面板标题栏右端一颗图标按钮，常驻、有条目时高亮并挂角标；**只有新冒出来的条目**才闪一下。两个面板都关着时弹一句 toast。首次扫描不算"新增"。
- 手动编辑：逐行就地改，同一时刻只开一个编辑框；保存时校验非空且不超硬上限——不是限制用户，而是防止"压完还是超长"，下次模型写入照样被拒。写世界书只动正文；写描述前若还有未处理 patch 直接拒绝。两条路径都**作废模型的读取登记**。
- 智能压缩目前是占位：入口、多选、提示词拼接都已落位，差调模型、结果预览、逐条确认写回三件事。
- 扫描是异步的，结果缓存成快照供界面同步读取；触发点全部去抖，并发扫描只让最后一次的结果落地。

## 17. 依赖的 ST 行为

不记行号——源码可搜。这些是会影响设计的**行为**：

| 行为 | 影响 |
|---|---|
| 注册的工具表为空时，请求体里连 `tools` 键都没有 | 聊天请求才能做到"与原生一致" |
| `quiet` 被排除在工具调用判定之外 | 会话请求体里的 `tools` 只能由插件自己写（§18） |
| 编辑器持有的是快照而非引用 | 写入后必须刷新编辑器（ADR-026） |
| 条目模板含空触发字段的语义 | 新建条目必须显式写（§11） |
| `generate_data.type` 保留这次调用的类型（`normal` / `quiet` / `swipe` 等） | 自建请求靠它确认"造出来的确实是 quiet 请求"，不符就停（§18） |
| `messages = messages.filter(...)` 造新数组但保留元素引用 | 任何挂上钩子的扩展都能原地改别人的消息对象——会话因此不走钩子（ADR-049） |
| `canPerformToolCalls()` 同时看后端能力与用户开关 | **与本插件无关**：会话的 `tools` 是我们自己写进 payload 的，这个开关只管 ST 自己的聊天请求。把它当前置判据会挡住本来能跑的学习（ADR-052） |
| `ConnectionManagerRequestService.sendRequest(profileId, messages, maxTokens, { extractData: false }, overridePayload)` | 指定连接配置时走它；`extractData: false` 才拿得到未解析的原始 JSON（默认会把 `tool_calls` 解析掉） |
| `extension_settings.connectionManager.profiles` 是配置列表，每项 `{ id, mode, name, api, model, preset }` | 设置页的下拉直接读它；只列 `mode === 'cc'` 的几份 |

## 18. 一次性内部会话

学习就活在这里（ADR-049 / ADR-050）。一场会话自带预设、消息栈、工具与超时，与当前聊天无关：**不占用用户的等待、不受消息编辑与后处理影响、不与对话共用提示词**。

**流程**：开始 → 填预设 → 发开场白 → 多轮工具调用 → 结束。五步各一个函数，`runSession` 只是组合体；`learning.js` 负责前后两头（拼目标内容、写回摘要）。

| 步骤 | 说明 |
|---|---|
| 开始 | 体检（这条路发不发得出去）+ 建内存对象。**此时不发生任何请求**，也不进聊天 |
| 填预设 | 卡片编译成若干段（每段带 role），宏在这里展开 |
| 发开场白 | 追加一条 user 消息：学习 / 压缩各一段，提示词编辑器里可改 |
| 跑循环 | 请求 → 解析 → 执行工具 → 把结果拼回去 → 再请求 |
| 结束 | 收尾，把摘要交给调用方写回对话状态。幂等 |

**隔离契约**（这几条是"解耦"的定义，破一条就等于没做）：

1. **不碰全局工具表**。会话的工具是自己的表，不注册进 `ToolManager`，因此不会出现在任何其他请求里。
2. **不碰 `extension_prompts`**。预设进的是会话自己的消息数组，主对话的注入一个字节都不变。
3. **不碰聊天消息**。不写 `mes`、不改 `chatId`；只写自己那份 `chat_metadata.thrive` 状态（上次结果、基线、patch、快照）。
4. **不挂事件钩子**。请求由插件自己发，payload 造出来之后只有自己能改。

**什么时候结束**：四种终止。

| 终止 | 含义 |
|---|---|
| 没有工具调用 | **正常跑完**。正文可以是空的，也不入栈——"这一轮没有值得记的东西"是合法结论 |
| 撞轮数上限 | **算没跑完**，结果可能不完整 |
| 被中止 | 用户 `/thrive stop`，或切对话时自动中止 |
| 工具报告致命 / 请求失败 | 循环立刻停下，不继续喂 |

另外两个前置停止：轮前预算估算超阈值（不等 API 报溢出）、请求失败 / 超时。

**"没调工具"与"跑完了"分开记**。`no_tool_calls` 与 `toolCalls === 0` 一起去回答"它到底干了什么"：摘要会写"没有调用工具（没有值得记的内容）"，而不是让用户以为失败了。

**同时只跑一场，其余排队**（ADR-052）。已经有一场在跑时再发起不会失败，而是进队列并立刻返回 `{ ok: true, queued: N }`——没有 promise，进度靠 `LEARNING_EVENT` 广播。这条互斥只管插件内部，**不覆盖**"用户同时在聊天区发消息"——两个请求可以同时在飞。

| 项 | 规定 |
|---|---|
| 上限 | 6 场（`MAX_QUEUE`）。满了才拒（`SESSION_QUEUE_FULL`），给一句"等几场跑完或先 `/thrive stop`" |
| 出队 | 前一场结束（成、败、被中止）时 `pump()` 取下一场。取之前先核 `chatId`，不属于当前对话的直接丢掉 |
| 中止 | `/thrive stop` 与面板的「停止」**连排队的一起清掉**：只停当前那场的话下一场会立刻接上，按钮看起来像没生效 |
| 落盘 | **不落盘**。排队是"我马上还要学一次"，进程重启后重放它没有意义，反而可能把旧内容当成新任务再写一遍 |
| 内容定型时机 | 教授在**入队时**就把那段话定型（用户此刻写下的）；"学这段对话"在**出队时**现取记录（要拿最新的） |
| 展示 | 面板状态行后面一颗「排队 N」；徽章 tooltip 与 `/thrive status` 也带一句 |

**连接配置一场只定一次**（ADR-052）。会话开始的时候读一次 `settings.connectionProfile`，整场不换：空 = 跟随当前聊天设置，走 `createGenerationParameters` + 直连端点；非空 = 交给 ST 的 `ConnectionManagerRequestService`，用那份配置的 api / 模型 / 密钥 / 端点。**预设不随行**（`includePreset: false`）：那是聊天那边的提示词，会话有自己编译的一份，两套一起发等于给模型两条互相打架的规则。中途换路会让同一场的前后两轮跑到不同模型上。选的配置没了 / 不是聊天补全，在开始那一步就以 `SESSION_PROFILE_MISSING` / `SESSION_PROFILE_UNSUPPORTED` 失败，不会跑到一半才崩。

**可观测性只有两处**：面板上那行状态（正在学 / 上次结果）与结束时的 toast / 徽章。没有界面、不落盘，刷新即丢。错误码本身不在这里列——看 `ERROR_HINTS` 里 `SESSION_*` 那一组，每条都写了下一步。
