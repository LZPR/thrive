## 三、缓存验证

后端（deepseek 直连）**不返回 `usage` / `cached_tokens`**，ST 源码里也没有 `include_usage`，所以按设计允许的兜底方案做定性判断：比对请求体前缀、学习块位置与工具表。

| 检查 | 结果 |
| --- | --- |
| 开关那一轮是唯一一次全量 miss | 关闭 → 开启：两条请求的**已有消息逐字节一致**（5 条 vs 12 条，差异只在多出的 assistant 回复、`tools` 表与尾部学习块）。关闭态请求体没有 `tools` 键、没有注入文本、没有插件字段——即"与未安装插件时的请求体无差异项"。 |
| 写入世界书后未命中关键词时前缀不变 | 条目写入只改世界书文件与 `chat_metadata.reads`，**不碰消息数组**；`setExtensionPrompt` 只有学习块一处，位置固定。实测连续两轮：第二轮的前 10 条消息与第一轮逐字节一致（多出的 2 条是本轮新增的消息与尾部学习块）。 |
| 学习块不打断前缀 | 学习块固定在消息数组**末位**（`index = 11 / 12`，即 `len-1`），相邻两轮的学习块文本完全相同（静态文本 + `char` 宏）。 |
| 工具表稳定 | 连续两轮的 `tools` 都是同样 4 个，顺序一致（开关没被反复拨动）。 |
| Step 09 的日志清理只产生一次断点 | `pruneToolTraces` 第一次清掉上一条用户消息之前的 Thrive 日志行，同一对话再调一次返回 0；混着别的工具调用的消息不动；`compressToolTrace` 只改写 Thrive 自己的消息且保留 `tool_invocations`。即：每轮最多一次断点，发生在被清理的那条消息处，之后不再动。 |

> 备注：请求体测试对话的尾部消息形如 `["system","[thrive] desc_read → {\"o…"]`、`["char","（角色回复）…"]`、`["user","（用户这一条）"]`——日志行确实只有一行、当轮压缩在 `role=system` 的独立消息里。

## 六、缺陷与修复（本次验收唯一一处代码改动）

**现象**：可写世界书被用户在外部删除/改名后，`lore_write` **写成功了**，并且 ST 的 `loadWorldInfo` 对不存在的书名返回了 `{ entries: {} }`（不是 `null`），于是写入路径把书文件凭空创建出来——用户会得到一本只装着插件写的那条内容的"幽灵书"。

**原因**：`src/targets.js` 的 `loadBook` 只用 `data` 是否为空判断书是否存在，而 ST 对不存在的书名返回的是空 `entries` 对象。

**修复**：`loadBook` 与 `readLore` 都改用书名清单（`ctx.getWorldInfoNames()`）判存在性，清单里没有就当书不存在：

- `loadBook` → `NO_BOOK` + "读不到世界书「X」，它可能已被删除或改名。请让用户重新选择。"
- `readLore` 的加载循环跳过清单里没有的书（否则会凭空多出一本空书，并让 `book:` 标记被写入）

**重测**：读 / 写都返回 `NO_BOOK`；测试期间被误创建的 `Thrive Gone.json` 已删除；`Thrive E2E.json` 字节未变。
