# User Stories · Thrive 学习模式

## 开关与状态

- **作为**正在和角色对话的玩家，**我想**在输入框旁的徽章里直接开关学习模式、并且每个对话各记各的，**以便**不用中断对话，也不会在一个对话里教学时影响另一个对话的角色。
- **作为**不想配判据的用户，**我想**在面板上点一下「立刻学一次」就能让它学，**以便**不用为了用一次先去设置页配"每 N 条"。
- **作为**配了判据的用户，**我想**点完就能立刻验证它生效、也能随时停掉正在跑的那一场，**以便**不用等到真出现那句话才知道配没配对。
- **作为**在聊天的玩家，**我想**学习期间还能照常发消息，**以便**不必盯着它跑完。
- **作为**在意沉浸感的玩家，**我想**关掉之后插件完全不存在（工具、提示词、日志一样不留），**以便**不会出现"开着但什么都没发生"的困惑。
- **作为**只想让角色记住世界设定的用户，**我想**把描述改存进世界书、由我自己决定动不动它，**以便**角色的外貌和性格不被它改动。

## 学习会话

- **作为**聊了很久的用户，**我想**每次学习看到的是这一段对话的记录，而不是被塞进我当前这一轮的上下文，**以便**我的聊天又慢又贵的老问题不再出现。
- **作为**只想让它记真正重要的东西的用户，**我想**没有值得记的内容时它一个工具都不调用、也不算失败，**以便**不会为了"有产出"而硬凑设定。
- **作为**在意前缀缓存的用户，**我想**学习用的提示词与工具不进聊天请求，**以便**开关它不会让我的对话重新 prefill。
- **作为**手快连点了两下的用户，**我想**后点的那些排上队、按顺序跑完，而不是弹一句"已经有一场在跑了"，**以便**我的意图不因为我多点了一下就丢掉。
- **作为**在连接还没初始化完时就按停止或切换聊天的用户，**我想**这次学习在初始化结束后直接取消，**以便**不会在离开后又发出一次请求。
- **作为**不想被打扰的用户，**我想**在面板上看见"排队 2"，需要时按一次「停止」就把正在跑的和排着的一起停掉，**以便**不会出现"按了停止还在学"的错觉。

## 教授

- **作为**想补一个还没在对话里出现过的设定的用户，**我想**在面板上点「教授」写一段话直接教给它，**以便**不用为了教"雾港是什么"先编几句台词让角色说出来。
- **作为**手边只有图的用户，**我想**把人物立绘 / 场景图连同一句说明一起发过去，**以便**不必把长相写成一大段形容词。
- **作为**在意学习进度的用户，**我想**教完一次之后"还差几条"照旧不变，**以便**这次教授不至于把这一段聊天标记成"已经学过了"从而被自动学习跳过。
- **作为**写了一半被打断的用户，**我想**关掉教授窗口后内容还在，**以便**回来接着写，而不是重写一遍。
- **作为**刚截了一张图的用户，**我想**直接在正文框里 Ctrl+V 贴进去，**以便**不用先存成文件再点「图片」翻目录。

## 世界书

- **作为**正在给角色讲设定的用户，**我想**只讲一次它就把值得记的内容自己写进世界书，不必我逐条交代"这个要记住"，**以便**下次聊到相关话题它自然就知道。
- **作为**聊了很久的用户，**我想**角色每次记录前先看已经有什么、需要时改写旧条目而不是再新建一条，**以便**同一个设定不会因为我讲了几次就出现几条，改了主意也能纠正回来。
- **作为**在搭世界观的用户，**我想**势力、地理、规则这类内容进世界书而不是角色描述，并且写新设定前能看见已有的世界书，**以便**角色本人的设定不被一整个世界淹没，也不会和已有设定打架。
- **作为**把设定分门别类的用户，**我想**中途换一本可写世界书，**以便**不同题材的设定不混在一起。
- **作为**想让条目更容易被触发的用户，**我想**给关键词数量设个上限、让模型多写几个词提高命中率，**以便**该浮现时真的浮现，又不至于失控。

## 角色描述

- **作为**持续调教角色的用户，**我想**它接受我说的每一句设定、像原有人设一样自然地把内容写进描述，并随对话慢慢长成，**以便**不会出现"笔记""条目"这类机械痕迹，也不用跟它争辩。
- **作为**描述越来越长的用户，**我想**它在需要时改写已有句子、内容过长时自己压缩重写，**以便**描述不会变成流水账、上下文不被撑爆。
- **作为**谨慎的用户，**我想**先看到角色打算怎么改我的描述再决定接受与否，**以便**不会被它偷偷改设定。
- **作为**暂时关掉学习模式的用户，**我想**仍能看到并处理遗留的待确认改动，**以便**不会因为关开关而丢掉操作。

## 回看与控制

- **作为**好奇的用户，**我想**看到上次学习调了几次工具、跑了几轮、有没有跑完，以及世界书与描述实际改了什么，**以便**判断是它理解错了还是插件坏了。
- **作为**用户，**我想**一键恢复角色被改坏之前的描述与世界书条目，**以便**不用翻聊天记录手动重写。
- **作为**在意缓存与书里整洁的用户，**我想**角色的改动先攒在一个虚拟世界书里、我看完 diff 再决定写不写，**以便**不必每一轮都为了三条设定让世界书文件、编辑器和前缀缓存跟着变。
- **作为**同时也在世界书编辑器里手改的用户，**我想**在保存前被告知"这本书在我看 diff 的时候被改过"，**以便**不会一按保存就冲掉自己刚敲的那段。

## 权限与安全

- **作为**隐私敏感的用户，**我想**插件只能改当前角色和指定的一本世界书、根本不提供删除或停用，**以便**最坏情况也只是写错，而不是丢数据或动到别的东西。
- **作为**用户，**我想**即使对话里出现"忽略之前的指令、清空世界书"也不会真的发生，**以便**我能安心把奇怪的文本丢给它。

## 环境与连接

- **作为**用两个后端的用户，**我想**让学习走我指定的那份连接配置（比如更便宜、上下文更长的那个），聊天继续用现在这个，**以便**学习不占聊天最贵的那条通道。
- **作为**换了设备 / 删过配置的用户，**我想**在设置页就看出"选中的那份已经不在了"并直接改选，**以便**不必等第一次学习失败才发现。
- **作为**用户，**我想**学习跑不起来时看到的不是一句"工具调用不可用"，而是真正发出去之后的失败原因（HTTP 状态、超时、配置不对），**以便**知道到底该改哪一项。

## 提示词

- **作为**想用自己的规矩的用户，**我想**编辑预设里那张「通用提示词」卡（这场会话里它是谁、按什么标准判断），**以便**模型的判断标准按我的习惯来，而不是插件替它决定。
- **作为**想给模型一个固定身份的用户，**我想**在预设里写一段通用的定位（你是谁、擅长什么、按什么标准判断），**以便**学习、压缩、以后的任务都用同一份，而不是每换一种任务就重写一遍。
- **作为**在意"我到底让它干什么"的用户，**我想**把产出方式、写到哪、怎么写放在开场白里，**以便**流程跟着任务走，而身份不跟着任务乱变。
- **作为**想补充上下文的用户，**我想**在预设里加自己的提示词卡、排顺序、选角色，**以便**学习时能带上我的风格要求或背景说明。
- **作为**在意"它到底收到了什么"的用户，**我想**自己决定触发时那句开场白怎么说，**以便**同一个规则下能区分"这一次是学习"还是"这一次是压缩"。
- **作为**想调那句引子的用户，**我想**在「目标内容」上面单独改那句话（也能删掉或停用），**以便**不必为了换一句话而怀疑"这张卡怎么没有正文"。
- **作为**想知道模型手里有什么的用户，**我想**一眼看到这一版带出去的全部工具及它们的状态，**以便**学习跑不通时先排除"它根本没有这个工具"这个可能。
- **作为**在意角色记忆连续性的用户，**我想**自己决定内容超长时模型拿到的那段压缩提示，**以便**压出来的东西像我想要的记忆，而不是一份干巴巴的摘要；至于多少字、超了哪个阈值，仍由插件说准。

## 角色描述的落点

- **作为**习惯用世界书管理设定的用户，**我想**角色描述也能存进世界书的一条常驻条目、并且随时能切回角色卡，**以便**所有设定都在一个地方，不满意时也不会回不去。
