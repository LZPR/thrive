# Thrive · 学习模式

SillyTavern 扩展。开启后给模型一组受限工具，让它把对话里值得长期保留的信息写进**世界书**和**角色卡描述**；关闭后插件对模型和请求体完全不可见。

两种打开方式：**主动**（手动开关，一直学）与**被动**（配好判据，命中就借一轮）。

适用版本：**SillyTavern 1.19.0**（2026-09-14）。单人一对一对话，不支持群聊。

## 它解决什么

角色扮演里的设定常常散落在聊天记录里：你讲了三次"北境在南边"，第四次它还是不知道。Thrive 让角色在对话过程中自己把这类信息记进 ST 原生通道（世界书条目、角色描述），下次命中关键词时自然带进上下文。

插件自己不保存任何"知识"——不建索引、不存摘要、不做向量检索。学到的内容 100% 落在 ST 的世界书与角色卡里，所以：

- 关掉插件，学到的内容照样生效；
- 卸载插件，学到的内容也还在；
- 插件侧只保留操作性状态（本轮读过什么、有没有待确认的补丁、上一版备份与最近几次写入记录）。

- **工具日志当轮压成一行纯文本**，发下一条消息时把旧日志移出上下文（界面里仍可见）
- `CHAT_CHANGED` / `MESSAGE_SENT` / `MESSAGE_RECEIVED` / `GENERATION_STARTED` / `WORLDINFO_SETTINGS_UPDATED` / `TOOL_CALLS_PERFORMED` 六处同步

## 工具

| 工具 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `desc_read` | 无 | `{ ok, chars, over_limit, text, hint? }` | 读 `description` 全文，不截断；有 patch 时返回暂存版并带 `staged: true`；超软阈值时带 `hint`（事实 + 压缩指令） |
| `desc_write` | `mode`, `text` | `{ ok, mode, added, staged \| applied, chars, note }` | `append` 追加 / `rewrite` 整段替换；`staged` 待确认，`applied` 已写入 |
| `lore_read` | 可省 `query` | 总览 `{ titles }` / 检索 `{ entries, hint? }` | 省略 query 只给标题，最多 `maxTitles` 个（默认 20）；检索时超软阈值的条目带 `over_limit`，`hint` 说明超了几条并附压缩指令 |
| `lore_write` | `title`, `content`, 可省 `keys` / `logic` | `{ ok, title, action, chars, keys, note }` | 按标题 upsert，`action` 为 `created` / `rewritten` |

- 目标由插件解析（当前选中的角色 / 设置里的可写书），工具参数里没有"角色 id""书名"这类字段。
- `over_limit = chars >= softLimitDesc`（默认 1600，可调），只做提醒，不拦截。
- 出错统一返回 `{ ok: false, error, hint }`，错误码清单见 `src/diagnostics.js` 的 `ERROR_HINTS`。
  另外补四个：`INVALID_MODE`（mode 不是 append/rewrite）、`INVALID_TITLE`（标题为空）、
  `WRITE_FAILED`（服务端拒绝或网络失败）、`PATCH_CONFLICT`（描述有一份冲突的改动等着用户处理）。
  每个错误码在 `src/diagnostics.js` 的 `ERROR_HINTS` 里都有一份兜底 hint：调用点的文案更具体就用调用点的，
  漏写时由 `errorResult` 回落到目录，不会出现裸的 `{ ok: false, error }`。
- **注册一次，永不增删**：开关与模块只改变 `shouldRegister` 的返回值。反过来在切换时
  register/unregister 会改变 `tools` 数组的顺序和内容，而 `tools` 位于请求头部，
  任何变化都会让整条前缀缓存失效（ADR-001）。
- 所有工具 `stealth: false`。stealth 会让 ST 在工具调用后直接 return，吞掉这一轮的正文（ADR-014）。

## 模块与权限

两个模块各管一半，开关在设置面板「允许模型写入哪些内容」：

| 模块 | 工具 | 注册条件 |
|---|---|---|
| 世界书 | `lore_read` `lore_write` | 对话开启 && `moduleWorldbook` && 可写书非空 |
| 角色描述 | `desc_read` `desc_write` | 对话开启 && `moduleDescription` |

**不降级**：目标模块关闭时返回 `MODULE_DISABLED`，hint 只说"不能写这个、现在还能记哪一类"，
**不给替代落点**。角色设定不会被偷偷塞进世界书，世界设定也不会被写进角色描述。

**两个都关**时整个扩展失去意义，于是：

- 输入框旁的徽章置灰；点开的面板里写明"两个模块都关着，请先在扩展设置里开启至少一个"，
  两个开关点了也只说原因、不切换状态
- 当前对话如果已经开着，会被**自动关闭**并提示一次——否则徽章亮着"学习"、模型却一个工具都看不到
- 面板状态显示「无可写模块」，两个开关下面各有一行提示

这个兜底放在 `refreshUI()` 里，所以手改 `settings.json` 把两个模块都关掉、再切对话时也会被纠正。

**关闭模块不动已有内容**：世界书条目和角色描述都留在原处，重新打开开关就又能读写。
面板只在对应开关下提示"学习块里关于这部分的段落建议一并删掉"——不自动改用户写的文本。

## 被动学习

不常开、但会自动「借」一轮。两条判据是**或**的关系，任一命中就触发一次：

| 判据 | 设置项 | 口径 |
|---|---|---|
| 条数 | 每 N 条消息触发一次 | 只数 `chat` 里非 `is_system` 的消息（工具日志不算）；一问一答算 2 条。0 = 不用这条 |
| 关键词 | 关键词（逗号 / 分号 / 换行分隔） | 只看**最近一条 User** 与**最近一条 Assistant** 的正文；大小写不敏感、子串匹配。世界书、作者注释、预设里的字**不算**——它们不是「这一轮说了什么」 |

一次触发的完整生命周期：

```
判据命中 → 挂上待学习（pending，只写内存）
        → 下一条消息构建提示词时当作"已开启"：注入学习块 + 注册工具
        → 角色消息落盘（MESSAGE_RECEIVED）→ 立刻结算：清掉 pending、进度归零
```

几条刻意的规则：

- **主动开着就不触发**，并把进度归零。否则关掉主动的瞬间会立刻补一次，看起来像开关自己亮了。
- **同一轮不重复触发**。结算时记下这一轮用户消息的哈希——角色回复里出现「我记住了」不会让下一轮再学一次。
- **中途停止不算结算**。结算挂在角色消息落盘上，而不是 `GENERATION_ENDED`（后者点停止也会发）。
- **静默生成不算**。`dryRun` 的摘要 / 翻译不标记、不结算，不会把用户等的那一轮学习吃掉。
- 开关与判据是**全局**设置；待学习记号与进度是**对话级**状态——换个对话看不见 A 的待学习，这是对的。

**触发时要看得出来**，三处一起给：

| 位置 | 表现 |
|---|---|
| toast | 一句话说清原因：「被动学习已触发（关键词「记住」）：下一轮对话临时开启学习模式，回复结束后自动关闭」 |
| 徽章 | 图标呼吸闪烁（系统开了"减少动态效果"则常亮不闪）；面板里的被动一行写出「本次待学习」 |
| 注入的学习块 | 末尾追加一段「本轮为自动触发、只在这一轮有效」，否则模型会以为学习模式一直开着 |

手动借一轮：`/thrive once`，或设置页「现在触发一次」。它不受总开关限制——用户明确要求就给他一轮，
也方便配完关键词后立刻验证。

### 徽章与面板怎么读

徽章只做一件事：**开 / 关浮动面板**。`/thrive panel` 打开的是同一个面板。

```
   🎓        灰：两个模式都没开        🎓¹     右上角数字 = 有 1 份待确认的描述改动
   🎓        强调色：主动开着           呼吸的 🎓  已挂上待学，下一轮借一次
   🎓        Em 掺正文色：只有被动开着
```

面板从上到下是「模式 → 待确认 → 已写入」。模式里每行左边是状态灯（亮 = 开），右边是「开 / 关」
按钮：有底色 + 加粗 = 开着，压暗的「关」= 关着。不可用时整行压暗，并写明是
「没有可写模块 / 没有对话 / 工具调用不可用」（ADR-024 的延伸）。

为什么徽章不再承担开关：它的宽度随文字变，混在 ST 那排固定尺寸的方块按钮里既不合群，
又会被 `#leftSendForm` 这个 flex 容器拉高；两个开关挤在 35px 里也放不下说明文字。

## 世界书读取

**可写书**：设置面板里的下拉，数据源是 `ctx.getWorldInfoNames()`（1.19 给的副本，不碰内部变量）。
选项上会标出两类需要留意的书：

- `（角色自带 · 改动会随卡分发）` —— 当前角色的 `data.extensions.world`
- `（疑似卡内嵌副本 · 不会自动同步）` —— 与卡内 `character_book.name` 同名

**读完范围**（`readScope`）：

| 值 | 读哪些书 | 返回 |
|---|---|---|
| `writable`（默认） | 只有可写书 | 条目不带 `source_book` |
| `bound` | 可写书 + `data.extensions.world` + `chat_metadata.world_info` | 每条带 `source_book` |

卡内嵌的 `character_book` 没有独立文件，`loadWorldInfo` 取不到，所以既不读也不写。

**两种调用**：

- 不带 `query` → `{ count, titles[], truncated, note }`，最多 20 个标题，不带正文。
  这一路**不登记读取**，否则"看一眼标题就能直接改写"，先读后写等于没有。
- 带 `query` → 在标题、关键词、正文里做不区分大小写的包含匹配，最多 8 条，
  每条正文截到 300 字（末尾加 `…` 标出截断，`chars` 仍是完整长度）。
  `count` 是匹配总数，可能大于返回条数。

**换书提醒**：本次读到的书与 `chat_metadata.thrive.lastBook` 不同时，返回 `switched: true`
和一句"这里没有之前那本书的内容，不要重复记录"（ADR-017）。换书确认后 `lastBook` 会被清空，
所以切换后的第一次读取一定会提醒。

> 注意：`lastBook` 是对话级的，新对话里第一次读取也会带一次 `switched`。这是有意的——
> 模型无法知道这个对话之前是否在别的书里记过东西，提醒一次比重复记录便宜。

## 世界书写入

**目标固定**：只写 `writableBook`，而且必须已存在。卡内嵌的 `character_book` 永远不是写入目标——
写入只会落到 `worlds/` 下的文件，两边会分叉（spec §11.1）。

**upsert 以标题为键**（`comment`），同书内定位：

| 情况 | 行为 |
|---|---|
| 书里没有这个标题 | 新建，`uid = max(现有数字 uid) + 1`（空书从 0 开始） |
| 已有 | 整条改写，`uid` 与在 `entries` 里的键都不变 |

字段映射：`title → comment`、`content → content`、`keys → key`、`logic → selectiveLogic`
（`any`=0 `not_all`=1 `not_any`=2 `all`=3）。省略 `keys` / `logic` 表示沿用原值。

**新建条目的固定值**在 `src/targets.js` 的建条目函数里，文档不抄清单（抄了必漂）。
唯一需要留意的偏离：`position` 取设置项 `entryPosition`，其余是常量。

> `triggers` 必须显式写空数组。1.19 的部分生成类型会读它，字段缺失的条目会静默不生效——
> 老书里那些没有这个字段的条目就是模板升级前留下的。

**改写时只动正文与显式给出的关键词/逻辑**，其余字段保留。尤其是 `constant`：新建时锁死 false
是为了不让模型白白占用上下文（ADR-008），但用户手工建的常驻条目，模型改写正文时不该顺手把它的
触发方式也改掉。

**落盘即刻**：`loadWorldInfo` → 改 `entries` → `saveWorldInfo(name, data, true)` → `updateWorldInfoList()`。
第三个参数必须为 `true`：默认走 debounce，切对话或关页面的那几百毫秒足以丢掉一次写入，而这条路径没有重试机会。
每次写入前都重新 load：`saveWorldInfo` 把对象按引用放进缓存，保存后再改同一个对象会造成"内存里改了、盘上没改"。

**校验**（守卫之后，spec §7）：

| 错误码 | 条件 |
|---|---|
| `NO_KEYS` | 新建条目没给关键词（当轮即被拒；否则是永不触发的死条目） |
| `EMPTY_CONTENT` | 正文空白（允许空内容等于给了一个删除工具） |
| `TOO_LONG` | 正文 > `hardLimitEntry`（默认 1200 字） |
| `TITLE_TOO_LONG` | 标题 > 60 字 |
| `INVALID_TITLE` | 标题为空 |

关键词数量超过 `maxKeywords`（默认 8）时**截断而不拒绝**，并在返回的 `note` 里说明截了几个。

**写了不等于会生效**：ST 只扫描**在扫描范围内**的书。三条路——角色自带
（`character.data.extensions.world`）、聊天级绑定（`chat_metadata.world_info`）、
以及在世界书面板里手动勾选。前两条之外的书，写进去的条目只是躺在文件里。

`selected_world_info` 没有公开 API，所以判定读 `#world_info` 的 `selectedOptions`
（`option.value` 是下标，映射到 `world_names`）。**插件不会替你勾书**（ADR-021），
但会把状态说清楚：

| 位置 | 未激活时 |
|---|---|
| `lore_read` 总览 | `note` 多一句"这本书当前没有激活，勾选后才生效" |
| `lore_write` | 照常写入，`note` 换成"不会进入上下文，请提醒用户勾选"；新建时再补"没激活就一次都不会触发" |
| 设置面板 | 可写书提示转警告样式，写明书没激活 + 去哪勾 |

已激活或判断不了时，`note` 保持原文案（"最迟下一轮生效"）——不能对模型说假话。

**不做**：删除、停用、`constant`、写卡内嵌书（ADR-011）。写错了只能靠快照或用户手动去
世界书编辑器里清理。

## 读写一致性

`desc_write` 的守卫顺序不可调（spec §8），先判"做没做过"再判"参数对不对"：

| 顺序 | 条件 | 返回 |
|---|---|---|
| 1 | 模块关闭 / 模式关闭 | `MODULE_DISABLED` |
| 2 | 没有选中角色 | `NO_CHAR` |
| 3 | 本轮没读过 | `READ_REQUIRED` |
| 4 | 读后内容被改（哈希不符） | `STALE_READ` |
| 5 | 正文空白 | `EMPTY_CONTENT` |
| 6 | 写入后总长 > `hardLimitDesc` | `TOO_LONG` |
| 7 | 已有 patch 处于冲突状态 | `PATCH_CONFLICT` |

- 第 4 步的"当前哈希"在暂存期间指的是 `patch.after`：模型看到什么，就以什么为基准，
  否则合并进同一份 patch 的第二笔写入永远过不了版本校验。

- `reads` 在用户**每次发消息时清空**，`patch` / `backups` 保留。
- 哈希是 FNV-1a（UTF-16 码元），只判断"变没变"，不做安全用途。
- 写入成功后立刻把新内容的哈希登记进去——不这么做，同一轮第二次 append 必然被自己的
  `STALE_READ` 挡住，模型会卡死在这里（ADR-007）。
- 直写前把旧值存进 `backups.desc`（只留 1 版）。这是手滑保险，不是版本控制。
- 写入走 `POST /api/characters/merge-attributes`，body 只带 `{ avatar, description }`。
- 长度按**写入后的总长度**算，不看本次增量。注意：卡片本来就长于 `hardLimitDesc` 时，
  append 会永远 `TOO_LONG`，此时只能 `rewrite` 交一份更短的全文。

`lore_write` 的守卫顺序相同，但"读没读过"在两张表上分别判：

| 情况 | 要求 | 否则 |
|---|---|---|
| 书里已有这个标题 | 读过**这条的正文**（`lore:<book>\|<title>` 的哈希） | `READ_REQUIRED` / `STALE_READ` |
| 书里还没有这个标题 | 看过**这本书**（`book:<name>` 标记） | `READ_REQUIRED` |

- 已有条目只给标题不算读过：否则"总览一下就能覆盖全文"，先读后写形同虚设。
- 新建条目只能要求看书，不能要求读正文——条目还不存在。少了这层，场景 1
  （读完发现书里没有 → 新建）会因为"读完一无所获、`reads` 里留不下痕迹"永远卡在 `READ_REQUIRED`。
- 写入成功后同时登记条目哈希与书级标记，同轮继续写别的条目不会被自己挡住。

## 描述改动暂存（patch）

角色描述每次都在 system 前缀里，改一次就让整段缓存失效，所以它是唯一走暂存的通道
（世界书即时写，ADR-005）。patch 只表达**一份差异**：`before` 是磁盘原文，`after` 是
模型想让它变成的样子，同一时刻最多一个（ADR-006）。

| 状态 | 含义 | 面板 |
|---|---|---|
| `pending` | 已暂存，等用户确认 | 接受 / 拒绝 |
| `conflict` | 暂存之后磁盘被改过 | 强制覆盖 / 拒绝 |
| `applied` | 已写入角色卡 | 已写入时间 + 关闭 |

**面板**：右下角的浮动卡片，只在有 patch 时出现。行级 diff，未改动行折叠成「⋯ N 行未改动」，
只保留差异段前后各 2 行作参照。超长的中文段落会按句读再切一刀——否则整段一行，改一个字就是
"整段删除 + 整段新增"。面板**只读**：只能整份接受或拒绝，不能在里面编辑 `after`。

**暂存期间（模拟叠加）**：

- `desc_read` 返回 `patch.after` 并附 `staged: true`，模型看得到自己刚写的东西。
- `desc_write` 的基准也是 `after`，所以同轮再写一笔就是往**同一份 diff** 上叠，
  `before` / `id` 都不变，不会产生第二条 patch。
- prompt 里仍然是**旧描述**。这个不一致是设计选择：patch 存在时也不往提示词里塞暂存内容
  （ADR-005/010 的代价）。

**接受**时先比对磁盘哈希：

- 一致 → 写入 `after`，状态转 `applied`，`backups.desc` 记下被覆盖的那一版。
- 不一致 → 转 `conflict`，**不写入**。不做自动合并——用户手写的一段和模型追加的一段谁在前谁在后，
  没有正确答案。强制覆盖时快照记的是**用户手改的那一版**，别把它弄丢了。
- 应用成功后立刻把 `after` 的哈希写进 `reads.desc`，下一轮不会误判 `STALE_READ`。

**拒绝**只清空 `patch`，磁盘不动，也**不动** `reads`：模型可能刚读到暂存文本，
把磁盘值的哈希写进去等于假装它读过，下一次写入就会基于没见过的内容覆盖磁盘。

**关闭开关**（`patchEnabled = false`）后回到直写（Step 04 行为），返回文案从 `staged`
换成 `applied`。有未处理的 patch 时开关会被拨回去，并提示先去面板处理——不允许静默丢掉（spec §10）。

## 浮动面板与恢复

右下角那块卡片分三段，由输入框旁的徽章开关。模式那一段始终在，记录两段有内容才出现：

| 分区 | 内容 | 动作 |
|---|---|---|
| 模式 | 主动 / 被动两个开关 + 待学提示 + 不可用原因 | 开 / 关（不可用时只给原因） |
| 待确认 | 描述 patch 的 diff、状态与元信息 | 接受 / 拒绝 / 强制覆盖（冲突时） |
| 已写入 | 世界书每次写入的一条记录：标题、动作、字数、时间 | 恢复写入前 / 撤销新建 |

**记录与快照是同一份数据**。`backups.lore` 的每一条既要在写错时能退回，也要在面板上占一行，
所以两件事合成一条：`{ id, book, title, action, before, beforeKeys, chars, at }`。
10 条上限（`loreBackupLimit`，可调）因此同时是"能退几步"和"面板显示几行"。

**两种恢复语义**，因为"写入前"的形态不同：

- `action = rewritten`：把 `content` / `key` / `comment` 写回快照里的值，其余字段（`position`、
  `depth`、用户手调的 `constant`）一个都不动。
- `action = created`：写入前这条根本不存在，所以按钮叫「撤销新建」，点下去是把条目从书里删掉。
  删除只发生在用户主动点按钮时——ADR-011 约束的是模型，不是用户。

恢复前弹一次确认，恢复后把该条标记成「已恢复」，并作废这一条的读取登记：书被插件动过，
模型下一次写入必须重新读，而不是拿着旧哈希去覆盖（`clearReadHash`）。

**描述只有 1 个槽位**（ADR-016）。「恢复上一版」写回 `backups.desc`，然后把槽位换成刚被覆盖的
那一版——这一步本身也能反悔，再点一次就换回来。有未处理的 patch 时不允许恢复：那份 diff 的
`beforeHash` 会对不上磁盘，恢复完必然转冲突，两件事会互相打架。

## 工具日志清理

ST 每完成一轮工具调用，会往 chat 里塞一条 `is_system` 消息，`mes` 是一大块 `<details>` 里包着
JSON 的 HTML，`extra.tool_invocations` 是同一批调用的结构化数组。两者都进上下文（`coreChat`
的过滤条件只看 `is_system` 与 `extra.tool_invocations`），于是日志随对话线性膨胀（ADR-013）。

两步治，都只做最小改动：

| 时机 | 动作 | 效果 |
|---|---|---|
| `TOOL_CALLS_PERFORMED` | 把 `mes` 改写成一行纯文本 | 当轮日志仍然看得见，但不再是 HTML + 完整 JSON |
| `MESSAGE_SENT` | 删掉"上一条用户消息之前"的 `extra.tool_invocations` | 字段没了，ST 自己的过滤条件把这些消息排除在上下文外 |

当轮不改结构：`TOOL_CALLS_PERFORMED` 在 `addOneMessage` 之前触发，改写 `mes` 之后渲染出来的
就是新文本；`extra.tool_invocations` 原样留着，第 2 步要靠它认出这些消息。

一行日志长这样（总长截断到 200 字）：

```
[thrive] lore_write → {"ok":true,"title":"北境","action":"created","chars":210,"keys":4,"note":"已写入。"}
```

结果里的长字符串只留长度（`"text":"…(2200 字)"`）、数组只留条数（`"entries":"8 项"`）——
`desc_read` 会把整篇描述返回给模型，原样塞进日志等于把刚省下的 token 又花回去。

**只处理"全部由 Thrive 工具构成"的消息**。混着别的插件的调用时不碰：替别人决定日志长什么样、
甚至把它们的调用记录一起删掉，不是本插件该做的事。代价是这种混合消息的日志仍按 ST 原生方式保留。

关掉设置里的「把旧工具日志移出上下文」（`dropTraces = false`）后，第 2 步整个跳过：日志按 ST
原生方式留在上下文里，费用回到没有清理时的水平。第 1 步的压缩不受这个开关影响——界面上仍然是
那一行文本，省的是"读起来费劲"，不是 token。清理只在 `MESSAGE_SENT` 触发，**重新生成 / 续写**
不经过这个事件，所以那些路径下旧日志会多留一轮——可接受，也省掉一次无谓的写盘。

## 环境诊断

设置页顶部一条状态：能用就中性色一句「工具调用可用」，不能用就转强调色，给出**原因**与**去哪改**。
结论只有一个来源——`ctx.isToolCallingSupported()`（ADR-020）；只有它返回 false 时才去读
`oai_settings` 的内部字段细分原因，顺序固定：

| 顺序 | 条件 | 结论 | 去哪改 |
|---|---|---|---|
| 1 | `main_api !== 'openai'` | 需要 chat completion 连接，当前是文本补全 | 「AI 响应配置 → 聊天补全来源」换成 Chat Completion |
| 2 | `function_calling` 为 false | 「启用函数调用」没勾上，ST 不会把工具发给模型 | 「AI 响应配置」勾上它（Continue Postfix 下面）；套预设会覆盖，换预设后要复查 |
| 3 | 后处理不是 `''` / `merge_tools` / `semi_tools` / `strict_tools` | 当前后处理会移除工具消息 | 改成 None 或带 `_tools` 的模式 |
| 4 | 以上都对 | 当前模型不支持工具调用（部分来源按模型能力判定） | 换支持 tools 的模型或来源 |

- 细分失败（字段改名、取不到设置）就降级成"判断不了具体原因 + 按顺序查这三处"，**不抛错**：
  诊断挂掉不该把设置面板一起带走。`isToolCallingSupported` 不存在时同样处理。
- 改 ST 那三个设置后诊断立刻跟着变（监听 `main_api` / `openai_function_calling` /
  `custom_prompt_post_processing` 等的 change 事件），不用刷新页面。
- **只检测、只告知**：插件不替用户打开 `function_calling`（ADR-020 的延伸），也不做分步引导。
- 工具不可用时徽章置灰，面板里只报第一条原因，两个开关点了不切换（ADR-024）：
  徽章亮着却一个工具都发不出去，比关着更容易误导人。

## 斜杠命令

| 命令 | 行为 |
|---|---|
| `/thrive on` | 开启当前对话；环境不可用 / 无可写模块 / 没有对话时直接说明原因 |
| `/thrive off` | 关闭当前对话 |
| `/thrive passive` | 切换被动学习总开关（全局）；关掉时把已挂的待学习一并丢掉 |
| `/thrive once` | 给下一轮挂一次临时学习（不受被动总开关限制） |
| `/thrive status` | 一行：主动 · 被动（判据与还差几条）· 模块 · 可写书（未激活会标出）· 待确认份数；有待学习时补一句 |
| `/thrive panel` | 打开右下角的浮动面板（与点徽章同一个）；模式开关在最上面，记录在下面 |

不写动作等于 `status`。命令只注册 `thrive` 一个前缀，不和 ST 内置命令重名。两处都输出：toast
（在输入框里敲命令时 ST 不会自己展示返回值）与返回值（给 STscript，如 `/thrive status |`）。

## 学习块

一段约 680 字（上限 1K）的系统提示词，告诉模型"什么时候值得记、记到哪里、怎么写，以及不清楚时怎么问"。它刻意不含任何动态内容（条数、模块名、待办数），保证整场对话这段文本恒定。

注入位置三选一：

| 位置 | 行为 | 代价 |
|---|---|---|
| `尾部`（默认） | `setExtensionPrompt(key, text, IN_CHAT, 0)`，落在消息数组最末 | 每轮重新计费，但不打断前缀缓存 |
| `头部` | `setExtensionPrompt(key, text, IN_PROMPT, 0)`，进 system 区 | 每次开关都会让整段 system 前缀重新 prefill |
| `不注入` | 插件不写，由用户自己放进预设 | 模型看得见工具却没有使用说明 |

- 注入前统一调用 `substituteParams()`，`{{char}}` / `{{user}}` 会替换成实际名字。
  这么做的原因：ST 对头部和尾部注入的宏处理路径不一致，只有插件自己替换才能保证两种位置表现相同。
- 编辑框留空 = 使用默认文本；「恢复默认」把 `blockText` 清回空串。
- `GENERATION_STARTED` 的 `dryRun`（摘要、翻译等静默生成）不注入。

## 压缩指令

内容写到接近或超过上限时，插件不会替用户删内容，而是在工具返回里附一段话让模型自己压。这段话分成两半：

- **前半是事实**，由代码拼：多少字、超的是软提醒还是硬上限、append 还能不能写、世界书是整条替换不能追加。事实随目标与当前阈值变化，所以不做成可配。
- **后半是提示词**，即设置面板里的「超长时的压缩指令」（`compactPrompt`），留空 = 用 `src/compact.js` 里的 `DEFAULT_COMPACT_PROMPT`，点「恢复默认」也回到空串。

默认文本约 90 字（参考上限 500，超过只把计数变红、不截断），只做三件事：说清为什么压（不压短就装不进上下文，之后的补充会一直被拒）、提醒压完要承认有东西记不清（别把没保住的细节当成还记得）、留哪些删哪些交给模型。规则写细了它就会照着砍成一份模板摘要，反而丢掉该留的东西。

生效的四个时机：`desc_read` 超软阈值、`desc_write` 超硬上限、`lore_read` 检索到超软阈值的条目、`lore_write` 单条超硬上限。

## 数值与上限

所有"写多少 / 读多少 / 留多少"的数字都在设置页「数值与上限」里，定义只有一份：
`src/limits.js` 的 `LIMIT_SPECS`（默认值 + 可输入范围 + 步进）。设置页的输入框按它渲染，
工具侧统一走 `readLimits(settings)` 取一套值，改完对下一次工具调用生效。

| 分组 | 设置项 | 默认 | 作用 |
|---|---|---|---|
| 世界书条目 | `softLimitEntry` | 800 字 | 单条正文的软提醒：`lore_read` / `lore_write` 的 `over_limit` 与 hint 按它判，不拦写入 |
| 世界书条目 | `hardLimitEntry` | 1200 字 | 单条正文硬上限：`lore_write` 写入后整条超过直接 `TOO_LONG` |
| 世界书条目 | `maxKeywords` | 8 个 | 关键词超过就截断（不拒绝），`note` 里说明截了几个 |
| 世界书条目 | `titleMaxChars` | 60 字 | 标题超过报 `TITLE_TOO_LONG` |
| 角色描述 | `softLimitDesc` | 1600 字 | 超过时 `desc_read` 返回 `over_limit` |
| 角色描述 | `hardLimitDesc` | 2400 字 | 写入后总长超过直接 `TOO_LONG`（append 也算总长） |
| 读取返回 | `maxQueryEntries` | 8 条 | 一次 `lore_read` 检索最多返回几条正文 |
| 读取返回 | `maxContentChars` | 300 字 | 每条正文最多给多少字，超出截断并标 `over_limit` |
| 读取返回 | `maxTitles` | 20 个 | 不带 query 时标题总览最多列几个 |
| 读取返回 | `softEntryCount` | 200 条 | 整本书条目数超过它就在返回里提醒合并 |
| 记录与日志 | `loreBackupLimit` | 10 条 | 面板「已写入」保留几条，也是能恢复几步；调小会裁掉多余旧记录 |
| 记录与日志 | `traceMaxChars` | 200 字 | 工具日志单行超过就截断 |

三条约定：

- **软提醒不高于硬上限**：两边随便填，但 `readLimits` 会把软提醒封顶到硬上限。软 > 硬意味着
  一条内容在被拒之前根本收不到提醒，这种组合没有意义；设置页底部会显示"当前生效"的实际值并标出这种情况，
  但不会去改用户填的数字。
- **0 / 空 / 超范围 = 回默认**：设置文件能手改，读到脏数据时照默认来，而不是让所有写入突然被拒。
- **改完不用重启**：每次工具调用现取设置；记录槽位在下次 `getState` 时按新值裁剪。

## 安装

### 从仓库安装（推荐）

ST 的「扩展」面板 → **安装扩展程序**，粘贴仓库地址：

```
https://github.com/<owner>/thrive
```

ST 这一步做的事就是 `git clone --depth 1` 到扩展目录，所以几条硬约束：

- **必须是 git 仓库地址**（HTTP/HTTPS）。`…/tree/main`、`?tab=readme` 这类页面链接和 zip 包都不行；要装别的分支或标签，填弹窗里单独的「Branch or tag name」。
- **仓库公开**。clone 不带任何凭证，私有库会失败。
- **`manifest.json` 在仓库根目录**，插件本体就是仓库根（ST 没有子目录安装参数，monorepo 里的一条子路径装不上）。
- **仓库名用 `thrive`**。安装后的文件夹名取自 URL 最后一段，扩展 id 随之变成 `third-party/<文件夹名>`，而设置面板模板按 `third-party/thrive` 渲染（`src/ui/settings.js`）——换个名字装上去，设置面板会是空白。
- 首次安装非官方仓库会弹一次第三方警告，确认即可；非管理员看不到「为所有用户安装」。

装完在扩展列表里启用 Thrive，刷新页面。之后列表里的「更新」就是 `git pull`；发版时 bump `manifest.json` 的 `version`，列表里才看得出更新。

### 开发期：目录联接

改完刷新页面即可，不需要拷贝：

```bat
mklink /J "<SillyTavern>\public\scripts\extensions\third-party\thrive" "<本仓库路径>"
```

没有管理员权限建不了联接，就把仓库内容同步到 `<SillyTavern>\public\scripts\extensions\third-party\thrive\`。

> 两种方式只能留一种：联接还挂着时点「安装扩展程序」，会因为目录已存在而失败（409）。
> 拆联接用 `rmdir "<…>\thrive"`（不带 `/s`），**不要**用 `rm -rf`——那会顺着联接删进仓库本身。
